# NODE 1차 안정화: 개발·테스트 회원 서버 권한과 입력 검증

헌법 제7조(접근 통제), 제16조(단계적 개발), 제18조(기존 기능/데이터 보호),
제20조(검증 우선)에 따른 기존 기능 안정화입니다. 서비스 기능이나 DB 마이그레이션을 추가하지 않습니다.
운영 Render 설정·Neon·실제 배포 환경과 001~005 SQL은 변경하지 않습니다.

## 검증용 역할과 관리자 분리

`npm test`는 기존처럼 **명시적으로 확인한 로컬 일회용 DB**를 초기화하고,
관리자 연결로 마이그레이션/가상 데이터만 준비합니다. 이후 `node_auth_runtime_<임의 ID>`
LOGIN 역할과 임의 비밀번호를 메모리에서 생성해 HTTP 서버에 전달합니다.
비밀번호/연결 문자열은 출력하거나 파일에 저장하지 않습니다.

기존 `tests/account.test.js`의 HTTP 서버도 제한 역할로 실행합니다.
해당 테스트의 매칭 SQL 픽스처와 DB 내부 회귀 테스트는 별도의 관리자 연결을 사용합니다.
매칭/지급/기록 기능을 이 회원 서버 역할에 허용했다는 뜻은 아닙니다.
테스트 종료 시 정책·역할을 제거합니다. 실패 시에도 정리를 시도합니다.

| 대상 | 회원 서버에 허용한 범위 |
| --- | --- |
| accounts | 로그인/화면에 필요한 id·email·password_hash·display_name 조회, 이메일·해시·이름 삽입 |
| account_sessions | 토큰 해시·계정·만료 시각 조회 및 세션 생성·삭제 |
| worker_profiles | 계정/경력 조회·삽입, 경력 개월 수만 수정 |
| account_roles | 조회·삽입. 행 보안 정책으로 worker/company만 추가 가능 |
| organizations | id/업체명 조회 및 업체명 삽입 |
| organization_memberships | 조회·삽입. 행 보안 정책으로 owner 등록만 가능 |

계정 수정/삭제, 업체 수정/삭제, admin/transporter 역할 부여, 임의 직원 권한 추가,
매칭·지급·활동/평가·심사 데이터 조회/변경, NODE 매칭 함수 호출을 허용하지 않습니다.
DB/역할/스키마 생성, 객체 소유권, superuser, BYPASSRLS, 역할 상속도 없습니다.
IDENTITY 자동 생성에 직접 시퀀스 권한이 필요하지 않아 nextval/currval 권한도 부여하지 않습니다.

PUBLIC의 TEMP/CREATE 권한이 우회 경로가 되지 않도록 해당 **로컬 테스트 DB**의
DB TEMP/CREATE와 public 스키마 CREATE를 회수합니다. 이 제한은 역할 정리 후에도 그 테스트 DB에 남습니다.
기존 행 보안 정책이 있거나 이미 역할 구성이 실행 중인 스키마에서는 덮어쓰지 않고 중단합니다.
역할·GRANT·정책 구성은 하나의 트랜잭션으로 수행합니다.

이 역할은 **서버 전용**입니다. 브라우저/사용자에게 직접 DB 접속이나 SQL 실행 권한을 주면 안 됩니다.
로그인에는 비밀번호 해시 조회가 필요하며, 회원 서버의 계정별 권한은 기존 인증된 세션과
고정된 SQL에서 검사합니다. 이번 두 테이블의 행 보안 정책은 역할 종류를 제한하는 정책이며,
전체 계정/업체 데이터를 사용자별로 격리한 완성된 다중 업체 RLS 정책은 아닙니다.

## 로컬 실행

Node.js 22 / PostgreSQL 16을 사용합니다. 예시는 비운영 일회용 DB 전용입니다.

```sh
npm ci
NODE_TEST_DATABASE=1 DATABASE_URL=postgresql://node:node_test_only@127.0.0.1:5432/node_test npm test
NODE_TEST_DATABASE=1 DATABASE_URL=postgresql://node:node_test_only@127.0.0.1:5432/node_test npm run dev:local
```

- 첫 명령의 DB는 테스트가 초기화합니다. 실데이터/운영 복제 원본에 실행하지 않습니다.
- `dev:local`은 준비된 동일 로컬 스키마에서 임시 최소 권한 역할로 서버를 시작합니다.
  마이그레이션이나 데이터 초기화를 수행하지 않으며 정상 종료 시 역할과 정책을 정리합니다.
- 초기 관리자 연결 문자열은 역할 준비/정리용이고, 실제 HTTP 서버의 DATABASE_URL에는 임시 역할을 넣습니다.
- 허용 호스트는 localhost/127.0.0.1/::1 및 테스트 컨테이너 `node-test-postgres`이며 DB명은 `node_test` 또는 `node_test_...`여야 합니다.
  명시적 `NODE_TEST_DATABASE=1`이 없거나 원격/다른 DB명이면 연결 전에 거부합니다.
- 테스트 런처는 제한 역할 URL도 관리자 URL과 같은 호스트·포트·DB인지 검사합니다.
- 일반 `npm start`와 배포 컨테이너는 기존 DATABASE_URL 설정을 그대로 사용합니다.
  이번 변경이 운영 역할을 자동 변경하거나 운영 최소 권한 설정을 완료하지 않습니다.
- 다른 앱이 사용하는 로컬 DB/공유 정책에 적용하지 않습니다. 별도 로컬 테스트 인스턴스를 사용합니다.

## 입력 규칙과 호환성

본문을 읽는 회원가입·로그인·경력 저장·업체 등록 API는 JSON 객체를 요구합니다.
JSON null, 불리언, 숫자, 문자열, 배열 또는 문법 오류는 HTTP 400을 반환하고 저장하지 않습니다.
기존의 빈 본문 처리/정상 객체 요청과 로그아웃 동작은 유지합니다.

경력은 0~900의 정수 숫자 또는 비어 있지 않은 십진 정수 문자열을 허용합니다.
예: `0`, `84`, `"0"`, `"84"`. 기존 숫자 문자열 호출도 호환되도록 했습니다.
null, 누락, 빈/공백 문자열, true/false, 배열/객체, 음수, 범위 초과, 소수는 400입니다.
실패한 요청은 기존 경력을 덮어쓰지 않습니다. 과거에 저장된 값은 추정해 수정하지 않습니다.

## 운영 적용 전 남은 조건

이 코드는 로컬 개발/테스트 역할 구성용이며 운영에서 실행하는 설치 스크립트가 아닙니다.
운영 적용은 별도 승인과 검토가 필요합니다. 실제 배포 역할의 권한/상속/소유권,
기존 정책, 연결 비밀, 백업을 확인하고 마이그레이션·런타임 역할을 분리해야 합니다.
테스트에서 생성한 자격 증명을 운영에 재사용하면 안 됩니다.
매칭 등 새 API가 생기면 별도 서비스별 최소 권한과 계정/업체 간 접근 통제를 설계해야 합니다.

## 검증 범위

기존 회귀 테스트를 전부 유지하고 제한 역할의 실제 로그인 연결에서 HTTP 회원 흐름을 확인합니다.
권한 거부, 관리자 역할 추가 차단, 잘못된 JSON/경력 요청의 무변경,
명시적 0과 정상 입력 호환성, 로컬 실행 안전 검사와 구성 중복 거부를 검증합니다.
회원 데이터 보존·마이그레이션 실패 롤백·동시 매칭 등 기존 DB 테스트도 그대로 실행합니다.
