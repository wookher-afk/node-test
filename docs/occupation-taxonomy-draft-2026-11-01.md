## 2. 코드 원칙

- 대분류 NODE-JM-001…, 중분류 NODE-JG-001…, 소분류 NODE-JO-0001…은 서로 독립된 불변 ID 초안이다. 숫자는 업무 우선순위나 상하위 경로를 뜻하지 않는다. 부모 ID 관계로 계층을 표현한다.
- 작업자와 업체는 동일한 소분류 ID를 사용한다. 역할별 ID나 별도 직종 사전을 만들지 않는다.
- 이름 변경·부모 이동 시 ID 유지. 삭제된 ID 재사용 금지. 통합 시 폐기 ID와 승계 ID, 분리 시 신규 ID와 이전 원문을 보존하고 모호한 과거 기록은 재선택 대상으로 둔다. 확정·개정 이력은 별도 카탈로그 버전으로 관리한다.
- 원문 출처는 파일/커밋/상수/원본 대분류/배열 순번으로 식별한다. 명칭만으로 과거 값을 자동 변환하지 않는다.
- 아래 분류는 기술/일반을 숙련 등급으로 단정하지 않는다. 기술·일반 구분은 별도 운영 속성 결정이 필요하다. 신입·보조·자격·경력·교육·규격은 직종 ID에 섞지 않는다.
- NODE-EO 코드는 장비기사 분리 검토용 예약 ID다. 기존 장비 kind ID나 DB occupation_id와 동일하지 않으며, 대응은 별도 승인 전까지 미정이다. 장비 자체는 기존 장비 분류 원천을 유지한다.

## 7. 향후 UI·저장 적용 설계 메모 — 구현하지 않음

1. 모집유형 “기술 및 일반작업자”에서는 JO 사전만, “장비기사만” 및 “장비+장비기사”에서는 기존 장비 사전만 사용한다. 영역 전환 시 숨겨진 이전 영역 값이 새 등록에 제출되지 않도록 한다. 이전 저장 문서 삭제는 별도 정책이다.
2. 처음에는 대분류만 노출. 대분류 선택 후 해당 부모의 중분류만 노출. 중분류 선택 후 해당 부모의 소분류만 노출. 하위 선택지 미리 노출·상위 자동선택을 하지 않는다.
3. 대분류 변경 시 중분류 ID·소분류 ID·직접입력 및 해당 직종 종속값 초기화. 중분류 변경 시 소분류 ID·직접입력 및 해당 직종 종속값 초기화. 초기화는 편집 중인 직종 행에 한정하고 다른 직종의 이력은 보존한다.
4. 소분류 변경 시 직종별 경력·자격·교육 등의 이전 종속값을 새 직종에 자동 승계하지 않는다. 이전 이력 보존 및 재연결 UX는 별도 설계한다. 장비 상세규격·옵션 필드는 기술·일반 영역에 섞지 않는다.
5. 작업자와 업체는 같은 카탈로그 버전과 같은 JO ID를 참조한다. 부모는 소분류 ID로 확인하며 임의 조합을 허용하지 않는다. 중복 방지는 같은 직종 코드 기준이되 경력 이력·모집 일정 단위는 별도로 설계한다.
6. 복원 시 카탈로그 버전/ID/부모 연결을 검증하고 유효한 선택은 순서대로 복원한다. 미확정·폐기·알 수 없는 ID는 원문을 보존한 재선택 상태로 두고 임의의 첫 항목으로 대체하지 않는다.
7. 포괄 직종과 전문 직종, 비슷한 명칭의 직종은 현재 자동 대체·동등 매칭하지 않는다. 구인 측이 어느 범위까지 허용하는지는 별도 매칭 정책이다.
8. 후속 승인 후 확인할 동작: 무선택→대분류→중분류→소분류 순차 노출, 상위 변경 초기화, 영역 전환, 복수 행 독립성, 양쪽 동일 코드, 저장·수정·재로그인 복원, 폐기 ID/직접입력 보존. 이번 작업에서는 화면·서버 테스트나 DB 접속을 수행하지 않는다.

## 부록 B. 보존 검증

작업 전 Git 추적 파일 및 무시되지 않는 미추적 파일의 SHA-256을 기록하고 작성 후 재대조했다. 기존 파일 변경·삭제 0건, 추가 파일은 본 설계 문서 1건뿐이다. DB는 접속·조회·수정하지 않았으며 원래 행 수를 재검증했다고 주장하지 않는다. 푸시·배포·병합·커밋 없음.
