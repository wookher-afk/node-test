# 03-3 구현 전 저장 결정 (2026-10-30)

사용자가 Q1~Q5와 보완사항 및 로컬 구현을 승인했다. 원 설계서는 설계 당시 기록으로 유지하며 본 결정이 충돌하는 문구에 우선한다. 이번 범위는 코드·테스트·로컬 검증이며 커밋·푸시·배포·DB·매칭 엔진은 제외한다.

- 전용 키 `node_03_3_credentials_v1`. 명시적 임시저장, 목록 저장, 삭제, 단계 응답, 검토 완료만 영속화한다. 입력·내부 단계 이동은 메모리만 변경한다. 목록 저장은 초안을 지우고 등록 있음으로 변경하는 단일 쓰기다. 나중에 보완은 목록을 유지하고 응답을 나중에로 저장한다. 마지막 삭제는 미응답으로 변경한다. 보유 없음은 빈 목록에서만 선택 가능하다.
- 03-2는 `node_03_2_a_v1`이 null일 때만 `node_03_2_v1`을 읽는다. 빈 문자열·손상·미지원 신키가 있으면 구키 폴백 금지. 추천에는 유효한 ability 기록의 id/mode/kind만 사용한다. 원본 키는 절대 쓰거나 지우지 않는다.
- Web Locks의 origin 공통 배타 잠금 안에서 읽었던 전체 원문과 현재 원문을 비교하고 일치할 때만 revision을 증가시켜 한 번 쓴다. 잠금 미지원은 쓰기 금지다. storage 이벤트는 안내에만 사용하며 충돌 후 자동 병합/재시도 금지. 화면 입력 내보내기 후 명시적 재불러오기를 제공한다. quota/접근/읽기검증 실패는 이동·성공 표시를 중단한다.
- 손상·미래 버전·알 수 없는 필드/enum은 기존 원문을 그대로 두고 읽기 전용으로 차단한다. 내보내기로 원문과 현재 입력을 각각 보관할 수 있다. 자동 초기화는 제공하지 않는다.
- 구 `node_worker_v05/v04/v03`는 사용자가 이전 기록 찾기를 누른 때만 읽는다. 항목별 canonical JSON(객체 키 정렬)의 SHA-256 + 동일 원문 출현 순번을 이관 식별자로 사용한다. 원본 키/인덱스는 출처 정보이며 순서 변경은 식별에 영향을 주지 않는다. 같은 원문은 키를 가로질러 중복 방지한다. 내용 변경은 새 후보이므로 기존 이름 중복 경고 및 사용자 확인이 필요하다.
- 가져오기 선택은 초안을 열기만 한다. 유형·명칭·날짜 상태를 사용자가 확인한 뒤 목록 저장해야 한다. 원 항목 전체를 legacy.raw로 보존하되 검증값으로 사용하지 않는다. 삭제는 해당 03-3 목록 항목과 그 원문만 삭제한다. 중복 방지 지문은 남겨 실수로 다시 가져오지 않는다. 초안 삭제는 명시적 취소 확인 후 초안만 지운다. 구 키·03-2 키는 삭제 대상이 아니다.
- 날짜 상태 변경 전의 값은 해당 기록의 previousDates에 보관하며 실제 날짜 비교에는 사용하지 않는다. 항목 삭제 시 함께 삭제한다. 무기한 별도 수정 이력은 만들지 않는다.
- 기술작업자는 03-2의 별도 진입 링크로 장비·기사 유형 검증 없이 03-3에 진입한다. 기존 03-2 다음 검토 동작은 유지하고 검토 영역에서 실제 03-3 링크를 제공한다. 03-3은 03-2로 돌아가며 공통 기술 프로필 URL을 추정하지 않는다. 작성 중 이동은 목록 저장/초안 보관/계속 작성 중 명시적 선택. 다음 목적지는 없으므로 검토 완료만 제공한다.
- 만료일 표현은 ‘만료일 기재 없음’으로 통일. 기종·톤수·법정 적합성 자동 판정은 하지 않는다. 카탈로그는 명세 S2~S5 공식 명칭에 한정하고 제한/과정은 사용자 확인 필요로 표시한다.
