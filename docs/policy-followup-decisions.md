## 권한·상태·원문 보존

근거는 이번 사용자의 직접 지시다: 기존 확정 C01~C04 A안을 보존하고, 감사 문서의 C05~C16을 원 정책과 대조해 어시스턴트 권고안으로 일괄 처리하도록 위임했다. 기존 대화의 미제시 승인 날짜·세부 수치·발언을 소급 창작하지 않는다. 과거 감사의 ‘자동 확정 금지’는 당시 상태이며 이번 명시적 위임과 기능 범위 예외를 구분한다.

- C01~C04는 이번 메시지에 명시된 기확정 내용을 보존한다. C05~C14는 아래 범위에서 위임 승인된 후속 운영 결정을 기록하며, 남은 법률·금액·제재 수치 검토는 확정으로 표시하지 않는다.
- C15의 아이디어와 C16의 실제 0.1 기능 범위는 **추천·별도 채택 승인 대기**다. 위임을 신규 기능 범위 확정이나 구현 승인으로 확대하지 않는다.
- P 50·B 103·SM 77, 원문 정책 총 230건과 기존 결정 이력을 수정하지 않는다. C01~C16은 감사 항목의 처리 결정이며 새 P/B/SM 번호 16개를 등록한 것이 아니다.
- 이 문서가 정한 충돌 적용 관계는 해당 감사 항목 범위에만 후속 기준으로 사용한다. 기존 원문은 감사 증거로 보존한다. 다른 무관한 원칙·제재·청구·법정 기간은 바꾸지 않는다.
- 코딩·DB·API·UI·배포·main 변경은 하지 않는다.

## C01 — 기확정 유지

검토 대상: 실질 상충: 표본 부족이면 산정 불가 vs 산정 가능 1건부터 비율 표시

관련: SM-67, P-20·P-21, B7-5·B7-16·B7-20. 근거: 이번 사용자 메시지가 보존하도록 명시한 기존 A안.

- 해당 지표의 산정 가능한 기록이 0건이면 ‘산정 불가’, 1건 이상이면 실제 비율, 1~4건이면 ‘기록 적음’을 함께 표시한다.
- 표본 부족을 낮은 신뢰·0점으로 바꾸거나 신규·무이력 회원을 기본 검색/자동매칭에서 배제하지 않는다.
- 취소율은 확정 매칭 계약, 완료·이행률은 산정 가능한 계약, 지급률의 소표본은 확인된 지급 회차로 구분한다. 지급률 자체는 B7-1의 금액 가중을 유지한다.
- SM-67의 ‘부족’은 계산 불가능한 0건 또는 필요한 사실/확인이 없는 상태를 뜻한다. 1~4건의 산정 가능한 기록을 숨기는 근거로 사용하지 않는다. P-21과 충돌하던 이 적용 범위는 기확정 A안으로 해결한다.

## C02 — 기확정 유지

검토 대상: 표현 규정 상충: 같은 0건 지표에 산정 불가와 산정 기록 없음 지정

관련: P-20·P-21, B8-1·B8-2, B7 표본 조항, SM-67. 근거: 보존 지시된 기존 A안.

| 층위 | 조건 | 표시 |
| --- | --- | --- |
| 계정 이력 | 거래 자체가 없음 | 거래 기록 없음 |
| 지표 산정 | 산정 가능한 기록 0건 또는 필요한 확인정보 없음 | 산정 불가 |
| 보조 사유 | 해당 지표·기간에 산정 기록 0건 | 산정 기록 없음(보조 설명) |
| 표본 경고 | 산정 가능한 기록 1~4건 | 실제 비율 + 기록 적음 |
| 실제 결과 | 산정 가능한 기록이 있고 결과가 0% | 실제 0%를 그대로 표시 |

최근 기록 0건을 전체 누적값으로 대체하지 않는다. 계정과 지표 상태를 같은 필드로 합치지 않는다. 기존 B8의 ‘산정 기록 없음’은 삭제하지 않고 보조 설명으로 연결한다. 원문 표시 문구의 병기/우선 관계는 이 기확정 기준을 따른다.

## C03 — 기확정 유지

검토 대상: 최소 진위정보는 확정됐으나 철회/만료 후 조회 주체·권한 기간 미정

관련: P-36·P-38~P-50, SM-74~SM-76. 근거: 보존 지시된 기존 A안.

- 작업자 본인은 자신의 발급·제출 이력을 확인할 수 있다. 철회·만료 후에도 기존 정당한 제출 관계가 확인되고 현재 해당 업체의 검증 업무 권한을 가진 담당자에게만 최소 진위 확인을 허용한다.
- 발급 사실·유효 여부·정정 여부만 제공하며 상세 근무 이력·비공개 개인정보는 제공하지 않는다. 원본/일반 문서 열람 권한을 되살리지 않는다.
- 확인번호·QR 소지만으로 불특정인이 조회할 수 없고, 본인 인증·제출 관계·현재 담당 권한·정당 목적을 각각 확인한다. 퇴사·권한 상실 시 즉시 조회를 종료한다.
- 조회 주체·대상·시각·허용/거부·최소 제공 범위를 기록한다. 허용은 적법하게 자료가 보존되고 검증 목적·현재 권한이 존재하는 동안으로 제한한다. 새로운 연수·일수는 정하지 않으며 로그/자료 보존기간은 C09의 별도 검토 대상이다.

## C04 — 기확정 유지

검토 대상: 분쟁률 분모·동일 계약 여러 분쟁, 업체 이행률 기간 귀속 등 지표별 정의 일부 부족

관련: P-09~P-12·P-17·P-24, B7, SM-70~SM-73. 근거: 보존 지시된 기존 A안.

- 공개 분쟁 지표는 계약 단위로 관리한다. 한 계약에서 분쟁이 반복돼도 해당 계약을 여러 계약으로 계산하지 않는다.
- 같은 계약의 반복 분쟁 횟수·사건별 상태·미해결 이력은 별도 항목으로 보존한다. 분쟁 발생과 확정 귀책을 합치지 않는다.
- 지급 회차·근무일수·분쟁 사건 수를 계약 건수로 대체하지 않는다. 계약·날짜·회차·사건의 연결과 지표별 포함/제외·기간 귀속은 기존 P/B7/SM-70의 확정 정의를 보존한다.
- 이번 메시지에 제시되지 않은 과거 A안의 추가 수치·승인 시각·완료되지 않은 상세 산식을 소급 창작하지 않는다. 지표 명세는 D06에서 이 계약 단위와 기존 지표 정의를 연결해 작성한다.

## C05 — 위임 결정

검토 대상: 내림차순/하한 필터가 낮을수록 좋은 취소율·분쟁률에도 동일한지, 유사 적합도 범위 미정

대조: P-19·P-20, B8-3~B8-6·B8-18, B7-21. 종전 B8-3의 모든 지표 ‘내림차순’ 및 B8-4의 일률 ‘하한’ 문구를 그대로 적용하면 낮을수록 유리한 지표의 방향이 뒤집힌다. 위임 승인에 따른 후속 적용 기준은 다음과 같다.

- 사용자가 직접 신뢰 정렬을 선택하면 완료율·이행률·실제/인정 반영 지급률은 높은 비율 우선, 귀책 취소율·분쟁률은 낮은 비율 우선으로 정렬한다. 거래 건수 선택 정렬은 많은 순으로 한다.
- 필터는 완료/이행/지급률·거래건수에는 최소값, 취소/분쟁률에는 최대값 의미로 제공한다. 무기록 포함 선택은 별도로 유지하며 기본 필터는 꺼져 있다.
- 무기록은 C01·C02로 표시하고 사용자가 직접 선택한 정렬에서만 후순위를 허용한다. 동률은 기존 B8-3의 산정 기록 수, 기본 정렬 순서를 따른다.
- 자동 추천은 법정·자격·일정·장비 등 필수 적합 조건을 먼저 확인한다. 작업 적합도와 선호를 계산한 뒤 유사 적합 후보 사이에서만 공개 가능한 신뢰 사실을 보조로 쓴다. 종합 신뢰점수나 신규 배제는 만들지 않는다.
- 지표 방향·선택 의미는 위임 결정이다. 유사 적합 구간·점수 가중치·거리 계산 등 숫자는 D 설계에서 검증 가능하게 명세하되 신뢰가 부적합 후보를 우선시키는 기준을 만들지 않는다. 새 가중치 수치는 이 문서에서 정하지 않는다.

## C06 — 운영 원칙 결정 / 금액·요금표 별도 검토 필요

검토 대상: 요금 부담자·표준 수수료 금액·권종 일반 유효기간·여러 혜택 사용 순서 미정

대조: P-03·P-05, B3·B4. **요금 금액·법적 청구/환급 세부·일반 유료권 판매조건은 별도 검토 필요**다.

- B3의 업체 귀책 보상권 1회·유효 1년·사용/청구 분리·귀책 반전 처리, B4의 작업자 1회 차감·현금 채무 없는 차감 대기·업체 면제 선부담·비소멸·반전 처리와 긴급 공고 노출은 그대로 유지한다.
- 발급·사용·차감 대기·업체 면제·청구·정정·환급을 별도 원장 이벤트로 추적한다. 같은 수수료 1회에 동일 면제 혜택을 중복 적용하지 않는다.
- 적용 가능한 혜택 중 사용자가 선택한 것이 있으면 적용 전 확인한다. 선택이 없으면 같은 대상의 먼저 만료되는 혜택, 만료가 같거나 없으면 먼저 발급된 혜택 순으로 처리한다. B4의 취소 자리 최초 대체 인력/다음 공고 첫 확정 적용 순서를 이 일반 규칙으로 뒤집지 않는다.
- 새로운 부담자·정액 채무·추가 과금을 만들지 않는다. 미정인 표준 수수료를 임의 금액으로 청구하지 않는다. 일반 유료권의 만료·환불 조건도 확정·판매하지 않는다. 요금표·법적 판매/환급조건 검토 전 금액이 필요한 운영은 완료 상태로 두지 않는다.

## C07 — 절차 결정 / 제재 수위·기간 별도 검토 필요

검토 대상: 플랫폼 위반 근거 검증·제재 수준/기간·담당 권한의 실운영 기준 미정

대조: P-08·P-14·P-23, B1, B8-60~B8-71, ADM-001. **제재 수위·기간·법률상 의무는 별도 검토 필요**다.

- 신고 사실·증빙·반박·확인된 플랫폼 위반을 분리해 기록하고, 허위 신고·계정 악용·기록 조작 등 운영 위반만 판단한다. 임금·손해배상 등 법적 귀책을 최종 판정하지 않는다.
- 접수 담당, 이해관계 없는 심사 담당, 이의 재검토 담당의 역할을 구분한다. 사건 이해관계자는 심사에서 배제하며 원 판단자가 단독으로 이의를 최종 재검토하지 않도록 한다.
- 기존 통지·7일 소명·14일 원칙 처리·7일 1회 이의 및 연장 사유 통지를 유지한다. 미소명·미인정 신고만으로 자동 위반을 확정하지 않는다.
- 확인 근거·적용 규정·처리 이유·통지·재검토를 이력으로 보존한다. 기존 당사자 간 임시 보호조치는 제재와 분리하며 위험 근거가 있는 B8-69의 재적용 요건을 유지한다.
- 구체 위반별 경고/이용제한 수준과 기간을 이 문서로 채우지 않는다. 기존에 허용된 보호조치를 근거 없는 전 계정 제재로 확대하지 않으며 제재표 검토가 끝나지 않은 운영을 완료로 표시하지 않는다.

## C08 — 위임 결정 / 법정 권리 세부 별도 검토 필요

검토 대상: 탈퇴 종결 사건 이의신청·진행 이의의 종결, 재가입 동일인 제재/직접 제외 승계, 계약 당사자 탈퇴 후 확인 경로 미정

대조: B8-63·B8-69·B8-72~B8-76, SM-77. 탈퇴 허용과 내부 사건 종결이라는 기존 확정을 유지한다.

- 어느 한쪽 탈퇴 시 그 내부 신고와 진행 중인 해당 사건의 재검토 절차를 ‘회원 탈퇴로 종결’로 종료한다. 위반 인정·기각·귀책 확정으로 바꾸지 않는다.
- 남은 당사자는 종결 사유·기록 오류에 대해 기존 B8-63의 기한/횟수 내 이의를 제기할 수 있다. 이는 종결 분류·기록의 정정 범위이며 탈퇴 종결 사건의 실체 조사를 재개하거나 탈퇴 계정 일반 이용을 복원하는 절차가 아니다. 법정 외부 권리·기관 절차는 제한하지 않는다.
- 재가입만으로 사건·임시 차단을 복원하지 않는다. 적법한 본인 확인으로 동일인이 확인된 경우 기존 정식 제재의 아직 유효한 범위와 직접 제외의 관계를 연결하되, 과거 신고 이력 자체로 감점·제재하지 않는다. 이름·전화 유사성·IP/기기만으로 동일인을 확정하지 않는다.
- 직접 제외는 검증된 동일 작업자·동일 업체 관계에 기존 효력대로 적용하며 종료된 지원·제안을 복구하지 않는다. 동일인 연결 근거는 최소 수집·권한 제한하고 보존기간/법적 근거는 C09 검토에 맡긴다.
- 계정 탈퇴가 확정 계약·미정산·이력 원본을 자동 취소·삭제하지 않는다. 일반 서비스는 종료하되 필요한 본인 확인 후 기록 열람·정정·미정산 자료 제출을 신청할 분리된 지원 경로를 둔다. 탈퇴자가 응답하지 않는다는 이유로 상대방 일방 신고를 양측 확인으로 바꾸지 않는다.
- 신고 철회는 B8-76의 별도 종결 사유로 기록하고 귀책 인정으로 간주하지 않는다. 철회된 그 신고의 임시조치는 종료하되 다른 유효 신고·직접 제외·정식 제재는 유지한다. 새 사건은 B8-68·B8-74의 새로운 사실/사유 기준을 따른다.
- 탈퇴 후 법정 정보주체 권리의 구체 처리 및 동일인 확인자료 수집 근거·보존은 별도 법률/개인정보 검토 필요다. 이 문서에 계정 재개를 의무화하는 기간이나 새 제재를 추가하지 않는다.

## C09 — 보호 원칙 결정 / 기간·근거 별도 검토 필요

검토 대상: 기록 유형별 목적·법적 근거·보존기간, 예외 보존 종료·담당자 범위 미정

대조: 헌법 제7·10조, B8-64·B8-72~B8-74, SM-66·SM-77, work-records-and-trust.md 개인정보 절.

- 기록 유형마다 목적, 개인정보 주체, 접근 역할, 시작/종료 사건, 삭제/익명처리, 법적 근거 및 보존기간을 별도 검토표로 관리한다. 현재 확정되지 않은 기간은 ‘별도 검토 필요’로 표시한다.
- B8-64의 신고·소명자료 사건 종료 후 3년 및 법령/진행 분쟁 예외는 기존 정책 수치로 보존한다. 이를 계약·지급·로그·제출 문서·알림 전체의 기간으로 확대하지 않는다. 3년 규정 자체의 법적 적합성이 이번에 법률 검증됐다는 뜻도 아니다.
- 민감 증빙 원본은 공개 저장소·일반 공개 프로필에 넣지 않고 별도 통제 저장 경로를 설계한다. 최소 정보와 연결 식별자만 업무 원장에 둔다. ID만 사용하는 것을 익명화라고 부르지 않는다.
- 제한 보존 자료는 일반 서비스 열람과 분리하고 담당 목적별 최소 권한·접근 로그를 적용한다. 분쟁 보존 예외는 대상·사유·책임자·해제 여부를 기록하며 자동 무기한 보존 사유로 쓰지 않는다.
- 보존 목적·법적 의무가 끝나면 삭제 또는 적법한 익명처리를 하며 파생 통계·사본·백업에 대한 전파·복구 시 재삭제 절차를 설계한다. 운영 원장의 불변과 적법한 삭제 절차를 별개로 관리한다.

| 기록 유형 | 지금 사용할 기준 | 남은 검토 |
| --- | --- | --- |
| 계약·지급·정정·귀책/보상 원장 | 당사자·사실·변경 계보 보존, 목적별 접근 | 근거·기간·예외·삭제 방법 별도 검토 필요 |

기간·근거가 필요한 실데이터 수집·보존 운영은 이 검토 없이 완료 또는 승인 상태로 표시하지 않는다. 법률상 새 기간을 제시하지 않는다.

## C10 — 위임 결정

검토 대상: 활성화 후 근무요일 전부 해제·정지 중 모드 변경·일반 수신중지와 자동모드 정지의 관계 미정

대조: SM-01~SM-15, B8-14·B8-15. 수신 허용은 모드별 날짜 조건과 각 제한 사유를 모두 만족해야 한다.

- 기본 요일이 0개면 자동 모드의 신규 탐색/제안 활성화를 허용하지 않는다. 활성화 후 요일을 모두 지운 경우도 같은 조건으로 신규 자동 제안을 멈추고 설정 보완 상태로 표시한다. 개인 설정·기존 제안·확정 계약은 보존한다.
- 일반 수신 중지, 자발적 일시정지, 신고 관계별 중지, 직접 제외, 정식 제재를 원인별로 분리한다. 한 원인의 해제가 다른 원인을 해제하지 않는다.
- 자동/선택 모드 전환은 자발적 수신 정지를 묵시 해제하지 않는다. 자동에서 선택으로 전환하면 SM-15대로 자동 재개 예약만 취소하고, 다시 자동으로 바꿔도 취소 예약을 복원하지 않는다. 정지는 사용자의 해제 또는 현재 유효한 자동 해제 예약으로만 해제한다.
- 저장된 선택 날짜를 복원할 때 지난 날짜 이력은 보존하되 현재 이후 유효 날짜만 신규 매칭 후보로 사용한다. 복원 후에도 개인 일정·개별 제외·확정 예약과 다른 제한을 다시 확인한다.
- 자발적 정지 중 기존 제안 기한은 진행하고 신고 중지만 남은 응답시간을 정지한다. 기존 수락 가능 제안과 확정 계약을 수신 정지로 자동 취소하지 않는다.

## C11 — 운영 해석 결정 / 시간제 제공 범위 추천 유지

검토 대상: 다일 제안 부분 수락/계약 변경·지난 선택일 복원·개인 일정 변경 알림 범위 미정

대조: JOB-008, DB-007·DB-009, B8-31~B8-44, SM-18·SM-25·SM-35·SM-68.

- 지원·제안·최종 계약에 참여 날짜 집합을 명시적으로 연결하고 조건 버전에 고정한다. 날짜를 뺀 수락이나 근무 범위 축소는 원 제안을 몰래 바꾸는 방식으로 처리하지 않는다.
- 부분 일정 허용 공고에서만 부분 지원·날짜 조정을 협의할 수 있으며, 새 날짜 집합과 조건은 양측이 다시 승인한다. 부분 지원 불허 공고는 전체 날짜를 기준으로 응답한다.
- 여러 날짜 중 하루라도 신규 매칭 불가면 제안 전체 상태만 상대방에게 안내한다. 특정 변경 날짜·개인 일정·휴무 사유는 공개하지 않는다. 이미 받은 제안 수락은 해당 제안에 한정한 예외이며 확정 예약 충돌 검사를 거친다.
- 개인 일정 추가/삭제·기본 요일·반복 휴무 변경 등 입력 원인과 무관하게, 유효한 미응답 제안의 실제 가능/불가가 바뀐 경우에만 SM-26~SM-64의 제한·통합·발송 규칙으로 알린다. 영향 없으면 알리지 않는다.
- 확정 계약 날짜 변경은 별도 합의와 충돌 재검증을 거친다. 개인 일정 변경이 확정 계약을 자동 변경하거나 법적 귀책을 확정하지 않는다.
- 현재 기반의 하루 단위 예약을 임의로 반일·시간제 서비스 지원으로 간주하지 않는다. 반일/시간제 제공·직종 범위는 C16 추천안과 별도 범위 승인 대상이며, 새 예약 단위 구현은 하지 않는다.

## C12 — 위임 결정

검토 대상: 관계 종료 후 신뢰 통계 열람 기간·선정 전 정당한 조회자·현장 세부 업무 권한 범위 미정

대조: P-15·P-16·P-30·P-33·P-36·P-42, B7-17·B7-19, pr-2-review-fixes.md.

- 조회는 ‘자료 소유자/당사자 또는 정당한 대상 관계 + 현재 역할 + 현장/업체 범위 + 업무 목적’으로 검사한다. 과거에 접근했다는 사실만으로 영구 권한을 주지 않는다.
- 선정 전 신뢰 통계는 현재 채용 권한을 가진 업체 담당자가 지원·제안·추천·정당한 작업자 검색 대상으로 확인할 수 있다. 작업자는 열람/지원하는 공고 업체의 허용된 통계를 확인한다. 공개 통계가 상세 거래·분쟁자료 접근을 허용하지 않는다.
- 관계 종료 뒤에도 현재 별도 정당한 검색/채용 목적이 있으면 같은 공개 통계 범위로만 조회한다. 과거 거래 당사자라는 이유만으로 모든 최신 상세 기록을 계속 열람하지 못한다. 목적이나 현재 권한이 사라지면 그 조회 경로를 종료한다. 임의 숫자 기한 대신 목적·권한 조건으로 한정한다.
- 기존 거래 상세는 고정된 거래 당사자 귀속과 현재 적법한 업무 권한을 모두 확인한다. 현장 이관·소속 변경으로 과거 거래 업체를 바꾸지 않는다. 퇴사·현장 권한 회수는 즉시 반영한다.
- B7-17의 미등록 ‘B14 후속 검토’는 새 B 번호를 만들지 않고 이 C12의 관계 종료 후 통계 접근 결정에 연결한다. 원문 참조는 보존한다.

| 주체/역할 | 허용 범위 | 차단 범위 |
| --- | --- | --- |
| 작업자 본인 | 본인 근무·계약·정산·발급/제출 이력 | 다른 작업자 상세 이력 |
| 현재 채용 담당자 | 정당한 후보의 허용 신뢰 통계·지원/제안 업무 | 현장 확인 권한 없는 근무 확정·미제출 상세 이력 |
| 현재 현장 근무 확인 담당자 | 부여된 현장의 대상 근무 확인·정정 절차 | 타 현장 확인·귀책 임의 확정 |
| 기존 정당 수신 업체의 현재 검증 담당자 | C03 최소 진위 확인; 유효한 별도 상세 열람권이 있을 때만 문서 본문 | 만료·철회·권한 상실 후 상세 본문 |
| 운영 담당자 | 배정 목적·사건 범위의 기록 관리·플랫폼 위반 심사 | 법적 책임 최종 판정·목적 없는 전체 열람 |

업체 소유자/관리자라는 이유만으로 모든 직원의 개인정보나 사건 증거를 무제한 열람시키지 않는다. 권한 부여·회수·행사 이력과 조회 목적은 D02에서 집행한다.

## C13 — 위임 결정 / 발송량 파라미터 기술 설계

검토 대상: 수령 확인 알림·정정 요청 미응답·반복 근무 재알림의 운영 빈도/요청 경로 미정

대조: P-29·P-31·P-32·P-35, B5, SM-65.

- 지급 신고 또는 상대 확인을 필요로 하는 기록 등록 시 확인 요청을 제공한다. 본인은 미확인 내역을 다시 확인하고 명시적으로 재요청할 수 있다. 이미 완료·종료·분쟁 절차로 이동한 일반 확인 요청은 새 일반 알림으로 반복하지 않는다.
- 근무 확인 최초 24시간 재알림·72시간 장기 확인 대기는 기존 확정대로 유지한다. 새 지급/정정 기한이나 반복 자동 발송 주기는 창작하지 않으며 추가 정기 재알림은 기본으로 도입하지 않는다.
- 같은 대상의 재요청은 이력을 남기되 불필요하게 반복 발송하지 않도록 통합·요청 속도 제한을 기술 설계한다. 일정 변경 알림의 30분 규칙을 지급·근무 알림에 일괄 적용하지 않는다.
- 상대방 정정 요청 미응답은 확인 대기를 유지한다. 미응답만으로 원본을 바꾸지 않고 이견·거부 시 기존 원본과 이의 이력을 유지한다. 운영자는 시스템 오류만 확인 정정하며 거래 사실 분쟁은 당사자/외부 절차로 남긴다.
- 장기 대기는 본인의 내역·요청 이력·지원 창구에서 관리한다. 미응답 자체의 자동 완료·귀책·신뢰 감점이나 운영자의 대신 수령 확인은 허용하지 않는다.

## C14 — 책임·검증 원칙 결정 / 법정 자격 목록 별도 검토 필요

검토 대상: 필수 자격 검증 수준·업체 제안한도 안전 상한·장비/운송 실제 확인 책임 상세 미정

대조: B8-7·B8-12·B8-13·B8-17·B8-18, EQUIP-003~EQUIP-009, LOG-001~LOG-006.

- 자격·장비 등록번호·소유/관리·기사 위임은 자가 신고와 출처/일시가 있는 검증 결과를 구분한다. 필수 조건의 증빙이 없거나 검증이 불충분하면 확인 대기이며 ‘검증 완료’로 표시하지 않는다.
- 법정 필수요건은 최종 확정 전 필요한 검증을 통과해야 하고 협의로 면제하지 않는다. 적용 직종별 법정 면허·교육·검증수단 목록은 **별도 법률·자격 검토 필요**이며 이 문서에서 법정 요건을 새로 열거하지 않는다.
- 공급자는 장비 정보·가용성·권한을, 현장 업체는 작업 조건·허용 옵션을 확인한다. 운송업자는 적재 규격과 운송 조건을 최종 확인하며 비용 부담자의 동의를 별도로 받는다. 각 확인자·근거·시간과 원본을 보존하고 NODE가 외부 사실을 법적으로 보증하는 것으로 표시하지 않는다.
- 제안 동시 한도는 기존 B8-12의 업체 설정값을 따르며 유효 제안 수가 그 한도를 넘지 않도록 하고 모집 완료·마감·제한 관계에는 추가 발송하지 않는다. 거절/만료/미선정 대상의 중복 금지는 기존 규칙대로 적용한다.
- 서버 자원 보호·전송 속도 제한·검증 재요청은 기술 설계로 두되 새로운 정액 한도·벌칙·서비스 이용 제한 수치를 만들지 않는다. 제품상 절대 상한이 필요해지는 경우에는 근거를 남겨 별도 검토하고 임의 수치를 넣지 않는다.

## C15 — 추천·미채택 상태 유지

검토 대상: 일반 민감 서류·전자서명·교육 알림·유류별 단가 상세는 원래 아이디어 상태

대조: DOC-001·DOC-002·WRK-001·JOB-001.

- 일반 민감 서류 전달, 계약서 자동 생성/전자서명, 안전교육 기한 알림, 유류 공급에 따른 계약 단가 상세는 별도 미확정 후보 상태를 유지한다. 기존 P-37~P-50의 본인 근무 이력 제출과 혼동하지 않는다.
- 추천안: 민감 서류는 목적·항목·수신자별 동의와 철회·접근 로그를 갖춘 뒤, 전자서명은 법적 효력·인증·원본 보관 검토 뒤 별도 채택한다. 교육 알림은 검증된 교육 기준/유효정보가 있을 때 검토하고 유류 등 비용항목은 급여와 구분해 협의 가능한 조건으로 설계 검토한다.
- 위 추천으로 새 수집항목·서명 효력·교육 유효기간·유류 금액을 확정하지 않는다. 아이디어를 확정 기능으로 승격하지 않는다는 처리 상태를 결정하며 실제 채택은 C16의 명시적 사용자 승인 대상이다.

## C16 — 추천안만 기록 / 사용자 범위 승인 대기

검토 대상: 첫 실제 이용 직종·지역·장비/운송 포함 범위·무료/유료 시작·핵심/후속 선택 미확정

대조: 헌법 제16·17조, 기능 후보 F01~F62와 전체 요구사항.

**기능 범위는 추천안일 뿐 확정하지 않는다.** 대상 직종·지역·장비/운송 동시 제공·수동/자동 제공 시점·하루/시간제 단위·무료/유료 시작·출시 일정·개발량은 사용자의 별도 명시적 승인 대기다.

- 추천: 계정/업체/현장·프로필/자격 → 지급조건 있는 공고·명시적 일정 → 검색/지원·직접 제안 → 같은 조건 양측 승인·일정/정원 보호 → 근무/계약 완료·지급/수령 독립 확인 → 객관 기록·통계의 한 흐름부터 설계한다.
- 권한·개인정보·취소/우천·미확정 사실·직접 제외·신고 보호·탈퇴와 기록 관리는 선택된 실제 제공 기능의 안전 조건으로 함께 설계한다. 자동 추천 정밀화·대규모 통합·문서/장비/운송 확장은 선행 의존성을 보고 후보로 검토한다.
- 장비 의존 직종이나 운송이 필수인 거래를 선택하면 관련 장비·운송 확인을 후속이라는 이유로 생략할 수 없다. 반대로 아직 선택되지 않은 분야를 이번 결정으로 출시 범위에 강제 포함하지 않는다.
- 기존 62개 기능 묶음의 후보 분류와 230개 정책의 등록 상태를 유지한다. 요금 미정은 무료 확정이 아니며 후보 우선순위를 개발 승인으로 바꾸지 않는다.

## 대조·검증·다음 작업

- C01·C02의 이전 2개 충돌은 위 기확정 A안으로 적용 기준을 해결했다. C05의 정렬 방향 등 새 해석은 원문의 종전 문구와 차이를 명시해 위임 결정으로 추적한다. 다른 기존 정책과의 적용에서 추가 직접 충돌은 검토 범위에서 발견하지 않았다.
- 모든 C 항목은 결정·기확정 보존·부분 결정 후 별도 검토·추천 승인 대기 중 하나로 처리했다. 법률 검토·금액·제재표·기능 범위가 남았는데도 모든 정책·사업 결정이 완료됐다고 표시하지 않는다.
- 감사/준비/기능/흐름 문서는 이 결정의 현재 상태를 반영한다. 원 정책·요구사항·기존 결정 이력·신뢰정보 본문은 보존한다.
- 기능별 상태·권한·데이터·예외 설계는 결정된 부분으로 착수할 수 있다. 수치·법적 근거가 필요한 운영, 실제 범위 확정, 구현·배포는 별도 단계다.
