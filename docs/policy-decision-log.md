### 기존 충돌·미결 사항의 해결 관계

- **SM-23·28·34:** 통합 단위는 동일 업체·동일 제안으로 통일한다. 여러 날짜도 하나의 제안으로 처리하고 다른 제안은 별개다. 30분은 SM-28을 유지한다. 이전 ‘날짜·업체 대 업체·제안’ 충돌 검토는 이번 후속 확정으로 해결됐다. 기존 SM-23 원문은 이력으로 보존하며 적용 해석은 SM-34를 따른다.
- **SM-19·20·22·25·26·35:** 단일·여러 날짜 모두 제안 전체의 가능·불가 상태만 안내하고 구체 변경 날짜·개인 일정·휴무 사유는 공개하지 않는다. 하루라도 불가하면 제안 전체 불가로 표시하되 자동 취소·응답기한 변경은 하지 않는다. 이전 날짜 정보 공개 경계는 이번 확정으로 해결됐다.
- **SM-30~33·36:** 통합 종료와 상태 변경이 겹치면 발송 직전 유효한 미응답 상태인지 재확인하고 처리된 대상의 대기 일정 알림을 폐기한다. 해당 처리 결과 알림과 구분한다. 과거 검토의 발송 직전 상태 우선순위를 이번에 확정했다.
- **SM-12·27·37~40:** 마지막 안내 상태와 현재 상태가 다르고 제안이 유효한 경우에만 마지막 알림 제한 해제 직후 최종 상태를 한 번 발송한다. 30분 대기는 적용하지 않고 다른 제한 사유가 남으면 억제를 유지한다. 정상 만료된 대상은 폐기·제외하되 신고 응답기한 정지는 SM-12로 판단한다. 이전 ‘필요한 알림’과 해제 후 발송 시점 미결은 이 범위에서 해결됐다.
- **SM-36·41~43:** 발송 직전 취소·수락·거절 상태이면 대기 일정 알림을 폐기하고 처리 결과만 안내한다. SM-41~43의 이미 발송 완료된 일정 알림은 소급 취소하지 않는 기준을 기록하며 다른 제안에 영향 주지 않는 원칙을 유지한다.
- **SM-28·29·38:** 일반 변경은 30분 통합, 응답기한 임박은 SM-29, 제한 해제는 SM-37~39의 조건 충족 시 즉시 발송이라는 명시적 예외 관계로 추적한다. 기존 차단 우선·기한 비연장 원칙은 유지한다.

앞선 SM-24~33 등록 당시의 통합 단위·날짜 공개·해제 후 발송 시점 미결 문구는 당시 검토 이력이다. 위 후속 확정으로 해결된 범위를 현재 미정으로 적용하지 않는다.

### 정합성 및 추가 확인 사항 — 임의 정책 결정 없음

1. **SM-36·42 / B8-11·19·41:** 신규 원문의 ‘수락으로 종료’는 일정 변경 알림 처리의 대상 상태와 관련되어 있다. 기존 B8-11은 제안 수락과 계약 최종 확정을 구분하며 양측 승인·확정 직전 재검증을 요구한다. 이번 알림 정책을 계약 자동 확정이나 전체 제안 생애주기 종료로 확대할 근거는 없다. ‘수락으로 종료’가 계약 또는 모든 후속 처리까지 종료한다는 의미라면 기존 B 정책과 충돌하므로 별도 사용자 확인이 필요하다. 원문은 그대로 보존하며 새 상태 전환 정책은 만들지 않는다.
2. **SM-37:** 해당 업체에 이전 안내 상태가 전혀 없는 경우의 비교 기준 및 ‘마지막 안내’가 앱 등록·푸시 전달·열람 중 무엇인지의 세부 정의는 미정이다. 최초 상태를 임의 생성하거나 항상 발송/생략하는 기본값을 만들지 않는다.
3. **SM-36·41~43:** 발송 직전 검사와 실제 발송 사이의 상태 변경·재시도에 대한 기술적 중복 방지, 이미 발송된 결과 알림의 재통지 기준은 미정이다. 이를 새로운 알림 권리·의무로 추가하지 않는다.
4. **SM-27·39 / B8-50·58·59:** 직접 제외로 이미 종료된 제안은 해제만으로 복구하지 않는다. 제한의 일부 해제는 발송 재개를 뜻하지 않는다. 신규 정책과 기존 종료·신고 중지 규칙 사이의 추가 직접 충돌은 검토 범위에서 발견하지 않았다.
5. 지원 철회와 제안 취소 경로의 세부 연결·알림 채널 등 이전 미결 중 이번에 명시하지 않은 사항은 유지한다. 과거 기록의 무관한 미결 사항을 이번 확정으로 자동 해소하지 않는다.
