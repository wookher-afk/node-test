# 필수 일치 조건 구현 및 검증 — 2026-11-01

## 적용 내용

최종 사용자 지시에 따라 체크박스를 각 조건 제목의 **왼쪽**에 배치했다. 오른쪽 배치와 모바일에서 제목 아래 한 줄을 추가하는 이전 안은 적용하지 않았다. 기존 제목, 항목 순서, 입력창 폭·높이, 기존 스타일과 선택 흐름을 유지했다. 선택 수는 기존 제목 옆에 `필수 일치 0/3`으로 표시한다. 체크박스의 접근성 이름과 마우스 툴팁은 해당 항목의 `필수 일치`임을 명시한다.

- 0~3개 허용. 세 번째 선택 이후 나머지 필수 일치 체크박스만 비활성화한다. 이미 선택한 체크박스는 해제 가능하며 해제 즉시 나머지가 활성화된다. 기존 입력창과 직종 체크박스는 제한하지 않는다.
- 업체: 모집 그룹 하나당 `line.requiredMatch` 배열을 저장한다. 그룹 추가 시 선택 수를 초기화하고 수정 시 해당 그룹의 배열을 복원한다. 그룹 사이에 선택이 전파되지 않는다.
- 작업자: `worker_alpha_registrations.document.requiredMatch`에 계정 프로필의 공통 배열 하나를 저장한다. 장비 등록과 기술·일반작업자 등록 화면이 같은 3개 한도를 공유한다. 다른 유형의 등록 문서가 아직 없더라도 공통 선택 수와 체크 상태를 복원한다. 기술·일반작업자 화면에는 기존 작업능력(직종) 항목만 있으므로 지역·급여·시간·일정 선택의 편집은 기존 장비작업자 희망조건 화면에서 수행한다. 기존에 없는 조건 입력창을 새로 만들거나 재배치하지 않았다.
- 여러 직종과 여러 운전 가능 장비는 `workAbility` 한 항목이다. 회사 그룹의 `occupationRequirement: all_per_person`를 그대로 유지한다. 사람 여러 명의 직종을 합쳐 충족하는 방식으로 바꾸지 않았다.

| 키 | 업체 모집 그룹 | 작업자 공통 프로필 | 원래 입력값 |

업체의 workAbility 체크박스는 기존 ‘모집 유형’ 제목 왼쪽에 있다. 원래 제목을 변경하지 않고, 선택한 유형의 직종/장비 조건을 하나로 지정한다. 현장 전체에 속한 주소·식사·숙소·자격 정보는 그룹별 필수 선택으로 임의 전환하지 않았다.

서버는 배열 여부, 최대 3개, 중복·알 수 없는 키·법정 면허 키 거부를 검증한다. 업체에서 작업 난이도·기타 계약 조건을 필수로 지정하면 해당 기존 입력값이 비어 있지 않아야 한다. 작업자에서 지역·급여·시간·일정을 필수로 지정하려면 해당 희망조건이 실제 저장돼 있어야 한다.

저장 스키마/마이그레이션 변경은 없다. 기존 JSON 문서에 선택 배열만 추가하며, 필드가 없는 기존 문서는 미선택으로 취급한다. 작업자 문서 수정 시 다른 유형 문서·알 수 없는 기존 루트 필드를 보존한다. 구형 클라이언트가 새 필드를 생략해도 기존 공통 필수 선택을 지우지 않는다. 명시적으로 `[]`를 저장하면 선택을 모두 해제한다. 기존 계정 소유권·버전 충돌 검사는 유지한다.

## 향후 매칭 정책과 법정 자격

공통 정책 모듈은 양측이 지정한 필수 조건을 모두 만족해야 한다는 향후 정책, 3개 제한, 그룹/프로필 범위, 작업능력 1개 계산, 법정 요건의 별도 필수 관문을 명시한다. 법정 면허·자격은 이 3개 배열의 선택 키에 포함되지 않는다. 기존 자격 자료와 03-3 저장 키/화면/분류 파일은 수정하지 않았다.

**자동 추천·후보 검색·양방향 일치 판정 엔진 및 법정 자격의 자동 판정 엔진을 이번에 구현한 것은 아니다.** 이번 범위는 체크 UI, 정책과 자료 저장, 서버 검증이다. 법정 자격의 존재나 유효성을 자유 입력 문구로 추론하지 않는다.

## 변경 전후 화면 비교

로컬 Chrome의 390×900, 1440×900 뷰포트에서 업체/장비작업자/기술·일반작업자 세 화면을 비교했다. 동일한 가상 로그인·빈 등록 상태에서 **기존 요소 총 198개**를 대조했다. 기존 제목 높이, 입력창/선택창/버튼의 x·y·폭·높이가 모두 동일하다. 체크박스와 선택 수가 들어가는 fieldset의 legend 글자 영역 폭만 늘어난다. 기존 입력 영역과 화면 전체 높이는 유지된다. 새 체크박스는 왼쪽에 있으며 제목은 한 줄로 유지된다. 실제 저장자료가 있는 화면에서도 제목 줄바꿈/가로 넘침/페이지 오류가 없음을 별도 검사했다.

## 검증 결과

서버 회귀 **147/147**, 기존 브라우저 회귀 **15개 스위트 전부 통과**. 새 기능의 실제 DB 브라우저 검사도 **390px·1440px 모두 통과**했다. 실제 프로젝트 DB의 **57개 테이블·297개 원본 행 해시가 모두 일치**했다. 다음 로그가 근거다.

- 서버 회귀: [server-regression.txt](server-regression.txt)
- 새 기능의 실제 DB·브라우저 390/1440px 검증: [ui-required.txt](ui-required.txt). 0~3개, 네 번째 비활성화, 해제 후 활성화, 복수 직종 1개 계산, 그룹 간 독립성, 수정/초기화/저장/로그아웃·재로그인, 다른 유형 문서가 없는 경우의 공통 선택 복원, 잘못된 요청의 저장 거부를 검증한다.
- 기존 UI 회귀: [ui-regression-results.json](ui-regression-results.json). 테스트의 원래 포트·브라우저 기본 설정이 이 환경과 달라 worker-postgres/03-2는 설치된 Chrome 및 별도 8052 테스트 서버를 지정해 재실행한 결과를 합산한다. 원래 테스트 파일은 수정하지 않았다. 검증 산출물도 이 폴더로 분리했다.
- 기존 DB 보존: [db-preservation.txt](db-preservation.txt). 실제 프로젝트 DB에 쓰는 테스트나 마이그레이션을 하지 않았다. 별도 폐기용 DB에서만 자료를 생성했다.
- 소스 보존: [source-preservation.json](source-preservation.json). 작업 시작 때 있던 파일의 삭제가 없으며 변경 파일은 명시된 기능 관련 8개뿐이다. 기존 직종/장비/면허 원본 및 앞선 미커밋 수정 파일의 나머지를 그대로 보존했다. 요청분만의 diff는 [session-changes.patch](session-changes.patch)에 있다.
