## 데이터 보존 방식

- 사용자 원본 Chrome·인앱 브라우저·프로필은 사용하지 않았다. 테스트마다 새 임시 브라우저 컨텍스트를 사용했으며, 기존 브라우저 localStorage를 읽거나 쓰지 않았다.
- 저장 키와 version을 바꾸지 않았고 기록·초안의 기존 필드와 알 수 없는 키를 유지한다. 기존 `node_03_2_v1` 원문은 읽기·보관만 하며 수정하지 않는다.
- 수량 상태를 바꿔도 보관 숫자를 지우지 않는다. 미입력 상태의 보관값은 현재 유효 제원으로 요약하지 않는다. 상태 키가 아예 없는 기존 수량은 원래 표시를 유지하며 편집 시 직접 입력 상태로 복원한다.
- 기존 등록 기록의 변경하지 않은 수량 원문은 숫자 변환이나 삭제 없이 재저장할 수 있다. 새 값과 변경한 값에 검증을 적용한다. 단, 새로 작성한 잘못된 초안은 자동저장·새로고침 후에도 등록을 차단한다.
- 기존 카고 빈값을 모름 또는 미입력으로 추측하지 않는다. 값은 빈 문자열로 남기고 `legacyEmpty`로 이전 응답 미확인임을 표시한다. 사용자가 상태를 명시적으로 고르면 해당 표시를 해제한다. 카고에 `stateRevision`, `dimensionStates`를 추가하되 기존 알 수 없는 키는 유지한다.

기존 테스트는 접힌 영역을 summary 클릭으로 여는 절차와 새 카고 상태 선택지를 반영했다. 신규 수량 입력 예시는 단위 없는 숫자로 바꿨으며, 기존 원문 보존 검증은 기존 기록을 주입한 뒤 편집·저장해 별도로 유지했다. 새 수량 검증에 맞지 않는 문자열을 통과시키기 위해 검증을 완화하지 않았다.

새 검증의 결과는 `fixed-results.json`, 크기 측정은 `fixed-metrics.json`, 큰글씨 화면은 `fixed-large-390.png`, `fixed-large-1440.png`, 상단 화면은 `fixed-top-390.png`, `fixed-top-1440.png`에 보관한다. 31항목 모두 큰글씨 모드의 390px·1440px에서 문서 가로 넘침이 없었고 필드명 글꼴 크기 20px 이상을 확인했다. 두 너비의 상단 이미지를 시각 확인했다.

## 사용성 측정과 제한

일반 글씨·빈 기록의 로더 폼 높이를 390px와 1440px에서 다시 측정했다. 변경 전은 각각 약 3,206px·2,022px, 변경 후는 약 2,307px·1,489px다. 문서 전체 높이는 변경 후 4,196px·3,107px다. 측정 원문은 `fixed-metrics.json`을 따른다. 선택 제원 접기로 처음 표시하는 폼 길이는 줄었지만, 펼쳐서 입력할 때의 전체 항목 수를 삭제한 것은 아니다.

사람의 실제 등록 시간은 새로 측정하지 않았다. 폼 높이가 줄었다는 이유로 등록 시간 단축률을 주장하지 않는다. 큰글씨 모드는 현재 페이지에서 전환하며 새로고침 후 선호 설정 복원은 제공하지 않는다.

기존 수량 원문에는 과거 잘못된 값이 남아 있을 수 있으며 이번에 일괄 정제하지 않았다. 자유 설명·복합 치수·단위가 포함되는 명명된 추가 원문은 단일 숫자로 강제하지 않는다. 실물 제원 범위의 타당성·정합성·인증 여부를 검증한 것은 아니다.

실제 가입 완료·서버 DB 저장·다음 가입 화면 연결, 실기기·Safari·스크린리더 전체 탐색, 대용량 성능은 이번 수정 범위 밖이다. 제품 코드 수정은 로컬에만 반영했으며 커밋·푸시·배포는 하지 않았다.
