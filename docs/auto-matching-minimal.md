# NODE 첫 자동 비교 엔진

현재 `worker_alpha_registrations`와 `company_alpha_registrations`의 저장 문서를 조회한다. 기존 UI, 등록 흐름, DB 스키마 및 데이터 변경 없음.

## 결과 확인

- 서버 재시작 후 로그인한 업체 구성원이 `GET /api/companies/{업체ID}/auto-matches` 호출. 다른 업체는 404. 응답에는 모집항목 ID, 작업자 계정 ID, 등록 버전과 비교 결과만 포함하며 연락처·원본 프로필은 반환하지 않는다. 새 API는 기존 로그인 인증 뒤에 연결되어 있다.
- 로컬 DB 직접 확인: `node --env-file=.env.local scripts/auto-match-preview.mjs`. 항목별 이유까지 보려면 `--details` 추가. 로컬 PostgreSQL만 허용하며 반복 읽기/읽기 전용 트랜잭션에서 SELECT 후 ROLLBACK한다. 기존 DB 초기화 도구는 사용하지 않는다.
- `checks`: pass / fail / unknown. `conditionStatus`: 필수조건 비교 결과. `status`: not_matched / indeterminate. `matched`는 현재 항상 false이다. 법정 요건 확인이 연결되지 않아 조건 통과도 확정 매칭으로 표시하지 않는다.

## 최소 비교 범위

양측 `requiredMatch` 합집합을 모두 적용한다. 선택 자료가 빠진 구버전은 선택 없음으로 추정하지 않는다. 모집 유형, 작업능력, 업체 최소 경력은 선택 여부와 무관하게 적용한다. 선택하지 않은 희망조건도 비교 결과에 표시하되 필수 게이트로 강제하지 않는다.

- 장비: 운전 가능 목록에서 기종·형태·규격 정확 일치와 요구 옵션 포함. 소유를 운전능력으로 간주하지 않는다. 최소 경력은 일치한 장비의 등록 연수 × 12개월로 비교한다.
- 기술직종: 동일 임시 분류 버전에서 한 사람이 요구 직종 전부를 등록해야 한다. 직종별 경력 미저장은 unknown.
- 지역: 같은 지역코드 체계에서 작업자 희망 지역이 업체 지정 지역 전체를 포함해야 한다. 자유입력 지역은 unknown.
- 급여: 같은 단위의 정수 원 금액에서 업체 제시액 ≥ 작업자 최소액. 단위 환산·허용 차액 추정 없음.
- 시간: 시작·종료 시각 정확 일치만 지원한다. 야간 시각도 원문 비교한다.
- 일정: 업체 지정 날짜/기간 전체를 작업자 가능 일정이 포함해야 한다. 업체 ‘항상 가능’에 실제 날짜가 없으면 작업자도 항상 가능한 경우 외에는 unknown. 실제 예약 중복은 조회하지 않는다.

## 미지원과 한계

법정 면허·자격·교육 검증 자료 및 적용 규칙 미연결 → 모든 조합에 독립 unknown 게이트. 브라우저 초안·본인 신고·자격명으로 충족을 추정하지 않는다. 장비 동반/선택형 모집, 직접 입력 장비의 동등성, 자유서술 작업·계약·지급·세금 조건의 상대측 수락은 미지원. 미지원 필수조건은 unknown으로 차단한다. 희망 시간 일부 겹침·협상, 인원 배정, 예약, 확정/저장, 추천 점수는 구현하지 않는다.

기존 내부 job_posts가 아닌 현재 Alpha 업체 등록 문서의 모집항목이 대상이다. 등록정보가 현재 공개 모집인지 판정하는 게시/마감 상태는 이 문서에 없으므로 결과는 내부 비교용이며 실제 배치 후보 확정이 아니다. API는 현재 저장된 전체 작업자와 해당 업체 모집항목을 비교하므로 대규모 운영용 페이지 분할은 미구현이다.

## 검증 (2026-11-01)

- 새 엔진 7개 + 기존 필수조건/작업자/업체 등록 관련 29개, 총 36개 통과. API 접근범위·조회 전용·응답 최소화는 요청 처리기 테스트로 확인. 실제 HTTP 로그인 통합 테스트는 이번 범위에서 실행하지 않았다.
- 실제 로컬 저장자료: 작업자 39명, 업체 16곳, 1,560회 비교. 조건 불일치 1,048, 판정불가 512, 확정 매칭 0. 읽기 전용 실행 완료.
- `server/index.js` 구문 검사 통과. 푸시·배포·병합 없음.
