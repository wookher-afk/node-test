# 업체 모집 그룹 검토용 구현 — 2026-11-01

미리보기: http://127.0.0.1:8048/company-registration

## 구현과 의미

- 기술 및 일반작업자: 모집 인원 → 대분류 → 중분류 → 소분류 체크박스 → 모집 그룹 추가 순서. 그룹마다 인원·직종·경력·급여·지역·일정을 지정하고 추가/수정/삭제한다.
- 그룹의 모든 인원이 선택 직종을 모두 수행하는 AND 조건이다. 직종별 인원이 다르면 그룹을 나눈다. 사람 여러 명의 직종을 합쳐 조건을 충족하는 조합형 매칭은 없다.
- 대분류/중분류 이동 중에도 선택 직종을 유지하며, 선택 요약에서 개별 해제한다. 저장 후 편집할 때 전체 선택 요약을 복원하고 원하는 분류로 이동해 체크 상태를 확인할 수 있다.
- 기존 장비기사만 / 장비+장비기사 유형과 장비 대분류·중분류·소분류·형태·규격·옵션 흐름을 유지한다.

## 공통 직종 데이터와 저장

`ui/03-2/occupations.js`는 설계 초안의 전체 179행을 추출한 공통 모듈이다. 대분류 13, 중분류 31, 소분류 179개이며 불변 코드와 부모 코드, 표시명, 출처를 분리한다. 카탈로그 버전은 `draft-2026-11-01-1`, 상태는 `draft`이다. 기존 설계 문서의 서비스 적용 금지는 이번 사용자 요청에 따라 로컬 검토용 적용으로 한정해 진행했으며 최종 분류로 확정한 것이 아니다.

모집 그룹은 기존 `company_alpha_registrations.document.lines` JSON에 저장한다. 기술 그룹 필드:

```json
{"resourceMode":"technical_worker","headcount":2,"occupationCatalogVersion":"draft-2026-11-01-1","occupationIds":["NODE-JO-0001","NODE-JO-0011"],"occupationRequirement":"all_per_person"}
```

기존 공통 급여·지역·일정 등의 조건과 그룹 ID는 유지한다. 서버에서 직종 존재·중복·버전·의미·정수 인원을 검사하고 장비 필드 혼합을 거부한다. 기존 장비 문서는 호환되며 이전 `either` 유형도 보존한다. DB 스키마 변경·미리보기 마이그레이션은 없다. 기존 소유권 검사와 버전 충돌 방지를 그대로 사용한다.

카탈로그 이름이나 부모 변경 시 코드 유지, 코드 폐기/통합/분리 시 별도 버전과 명시적인 이관 정책이 필요하다. 과거 값을 이름으로 자동 변환하지 않는다. 이번 공통 모듈을 향후 작업자 등록에서 직접 가져와 동일 `NODE-JO` 코드를 사용할 수 있다. 기존 장비 카탈로그 버전 2와 직종 초안 버전은 독립적이다.

## 확인한 범위와 미해결 사항

- 기술·일반작업자 전용 `web/technical-registration.html`은 현재 준비 중 안내만 제공하며 실제 직종 선택·저장이 불가능하다. 기존 작업자 API도 기사 역할과 운전 장비를 필수로 요구한다. 전용 화면뿐 아니라 역할·검증·저장 계약까지 확장해야 하므로 별도 작업으로 분리했다. 작업자와 업체의 실제 직종 기반 매칭이 완료됐다는 의미는 아니다.
- 기술/일반 구분 자체는 초안에서 확정하지 않았으므로 임의로 직종을 양분하지 않았다.
- 자동매칭 엔진·알림·결제 구현 없음. 외부 주소 검색 서비스 자체는 이번에 재검증하지 않았으며 저장 왕복 테스트에는 합성 주소 선택 콜백을 사용했다.
- 기존 미커밋 변경을 초기화/되돌리지 않았다. 원격 푸시·배포·병합·커밋 없음.
