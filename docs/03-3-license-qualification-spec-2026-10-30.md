## 1. 검토 결과와 설계 원칙

03-3은 작업자 본인이 면허·자격·교육 이수 정보를 복수 등록하고 이후 보완하는 화면이다. 가입 완료, 본인 신고, 실제 검증, 작업별 법정 적합성은 각각 구분한다. 장비 운전 경험이나 자격증 취득만으로 조종사면허를 발급받았다고 추정하지 않는다.

권고 기본안은 ① 면허/국가기술자격/교육 분리 ② 가입 단계 건너뛰기 허용 ③ 이름·종류 중심 최소 수집 ④ 전부 본인 신고·미확인 표시 ⑤ 증빙 업로드 제외 ⑥ 법정 요건 작업은 확인 전 매칭 확정 보류다. 법적 요건별 매핑과 검증 수단은 별도 검토·승인 후 도입한다.

## 2. 화면 범위와 사용자 구분

- 화면명: **03-3 면허·자격 등록**. 보조 설명: ‘면허, 자격증, 교육 이수 내역을 따로 등록해 주세요. 등록만으로 확인이 완료되지는 않습니다.’
- 장비작업자: 운전 가능 장비와 관련된 조종사면허·자격·교육을 우선 추천. 자가기사/데모기사는 03-2의 기사 유형이며 장비/기술 작업자 구분과 다른 축이다.
- 기술작업자: 등록 직종을 바탕으로 자격·교육 찾기를 우선 표시. 장비 미등록 정상 허용. 숙련·경력은 자격증과 별도다. 신호수·보조인력이라는 직종명만으로 면허 보유나 교육 의무 면제를 판정하지 않는다.
- 복수 역할: 두 분류 동시 선택 가능. 같은 사람의 자격을 역할마다 복제하지 않고 관련 직종·장비를 연결한다. 역할 변경으로 자격을 삭제하지 않는다.
- 역할 출처 미연결: 기존 화면에 없는 역할 값을 추측 생성하지 않고 전체 항목 찾기와 사용자 선택을 제공한다. 이후 공통 프로필 연결이 필요하다.
- 포함: 복수 추가·수정·삭제, 초안·복원, 목록, 이전/다음 설계, 추천 설명, 미확인 안내.
- 제외: 사진·PDF·카메라·OCR·파일 URL 입력, 증빙 업로드·전달, 외부 진위조회·검증 요청 접수, 관리자 심사 UI, 법정 매칭 엔진, 만료 알림, 실제 가입 서버 연동. 화면에 작동하지 않는 ‘검증 요청’ 버튼을 두지 않는다.

## 4. 03-2 연계와 추천

추천은 가능하다. 목적은 입력할 항목을 찾기 쉽게 하는 것이며 법정 요건 판정이 아니다.

| 입력 근거 | 보여 줄 추천 후보 | 제한 |
| --- | --- | --- |
| `records.mode=ability`, `kind=excavator` | 굴착기 관련 조종사면허 / 굴착기운전기능사 / 관련 교육 항목 찾기 | 세 가지 독립 카드. 소형 제한은 직접 확인. ‘017’ 등 현장 규격을 톤수로 환산하지 않음 |
| `kind=forklift` 운전 가능 기록 | 지게차 관련 면허·국가기술자격·소형 조종교육 찾기 | 정격하중·실제 기계 분류 불명확 시 제한 면허를 단정하지 않음 |
| 기타 장비·기술 직종 | 검토된 연결표가 있으면 관련 항목 찾기 | 미검토 매핑은 일반 검색으로 안내. 추천 0건도 정상 |
| 보유 장비만 등록 | 전체 항목 찾기 또는 사용자가 운전 여부를 확인한 뒤 추천 | 소유자=운전자 추정 금지. `operator`가 기사 제공이어도 본인 자격 추정 금지 |

- 같은 기종 여러 대는 추천만 중복 제거한다. 관련 원본 record ID는 모두 유지한다.
- ‘굴착기 운전 가능 장비를 등록해 관련 항목을 보여드립니다. 실제 보유한 항목만 선택하세요.’를 표시한다.
- 후보 선택은 폼을 열 뿐 목록 추가·보유 체크·검증 완료로 저장하지 않는다. 추천 숨기기 가능.
- 03-2는 읽기 전용 참조. 추천 계산 실패·미등록·손상·알 수 없는 ID가 있어도 03-3 직접 입력 가능. 손상 원본은 자동 복구·이전 키 대체 금지.
- 장비 수정/삭제 후 추천만 재계산한다. 자격 기록·초안과 과거 연결 ID를 연쇄 삭제하지 않고 ‘연결 장비 변경됨’을 표시한다.

## 5. 모바일 단계형 화면과 이동

기본 1열, 본문·입력 18px 권고, 큰글씨 22px 권고. 보조문도 함께 확대한다. 터치 영역 최소 48px, 키보드 접근·명시적 라벨·색 외 텍스트 상태·오류 포커스 제공. 320/360/390px 및 글자 200% 확대에서 가로 넘침 없이 재배치한다. 고정 하단 버튼은 키보드·오류·마지막 입력을 가리지 않는다.

| 화면 내부 단계 | 노출할 입력 2~3개 | 행동 |
| --- | --- | --- |
| 시작/목록 | 등록 건수·상태 / 추가 유형 선택 / 관련 항목 추천(접기) | 면허 추가·자격증 추가·교육 추가, 나중에 등록 |
| A 종류 선택 | 유형 / 이름 또는 검색 / 제한·세부종류(필요 시) | 해당 면허·자격을 구분하는 도움말과 공식 자료 링크 |
| B 기본 정보 | 취득·이수일 상태 / 날짜(아는 경우) / 발급·교육기관(선택) | 날짜 모름을 명시적으로 선택 가능 |
| C 유효기간·연결 | 만료일 상태 / 날짜(있는 경우) / 관련 장비·직종(선택) | ‘만료일 기재 없음’과 ‘모름’ 구분. 제한명 입력은 A에서 완료 |
| D 확인·목록 저장 | 신고 요약 / ‘직접 입력·미확인’ 안내 | 추가 저장 또는 수정 저장. 또 등록/목록/다음 제공 |

날짜의 상태와 날짜값은 하나의 질문 묶음으로 표시한다. 목록 전체는 입력 단계 수에 포함하지 않는다. 장비·직종 연결처럼 선택항목은 기본 접기 처리하고 한 번에 긴 폼을 펼치지 않는다. 제목 ‘03-3’과 내부 ‘1/4’ 진행도를 구별한다.

- 목록 카드: 유형·명칭·제한, 취득/이수일(또는 모름), 사용자 입력 만료정보, ‘직접 입력·미확인’, 수정·삭제. 기관은 상세에서 표시한다.
- 이전: 내부 단계에서는 한 단계 뒤로, 목록의 ‘03-2 장비로’는 장비작업 경로에 표시. 기술작업자는 해당 이전 프로필 단계로 이동. 현재 코드의 실제 경로가 없으므로 URL을 임의 확정하지 않는다.
- 다음: 목록 저장 성공 후 후속 등록 단계로 이동. 희망 근무 조건 보완 → 일정·수신 설정이 권고 순서이며 다음 화면 번호·URL은 미확정. 목적지가 없으면 검토 완료 화면으로만 안내하고 ‘가입 완료’라고 쓰지 않는다.
- 작성 중 입력이 있으면 ‘목록에 저장하고 이동 / 초안만 보관하고 이동 / 계속 작성’ 선택. 필수값 오류가 있으면 목록 저장 이동은 불가하지만 초안 보관은 가능하다. 자동 목록 추가 금지.
- 목록 0건: 응답 없이 일반 다음을 누르면 ‘지금 등록 / 나중에 등록 / 보유 항목 없음’ 선택. 건너뛰기 자체를 면허 없음으로 저장하지 않는다.
- 이미 목록이 있으면 ‘나중에 보완’은 목록을 유지한다. 항목 모두 삭제해도 과거 건너뛰기 사유를 자동 부여하지 않는다.
- 삭제: 명칭을 포함해 확인. 취소하면 목록·초안 유지. 저장 실패면 삭제를 확정 표시하지 않는다. 수정 취소는 원본 목록 유지.

## 6. 입력항목·필수/선택·최소 수집

‘필수’는 **항목을 목록에 추가할 때** 기준이며 가입 전체 필수라는 뜻이 아니다. 임시저장은 불완전 입력도 보존한다.

| 항목 | 권고 필수성 | 의미·검사 |
| --- | --- | --- |
| 면허/국가기술자격/교육/기타 구분 | 필수 | 이름이 같아도 유형별 별도. 기타는 분류 확인 필요 |

| 취득일/면허 발급일/교육 이수일 상태 | 필수 응답, 날짜값 선택 | 정확히 앎 / 모름. 정확히 앎이면 유효 날짜 필수. 면허 최초 발급일과 재발급일 혼동 안내. 재발급일로 교육 기산일 자동 변경 금지 |
| 만료일 상태 | 필수 응답, 날짜값 조건부 | 기재된 만료일 있음 / 만료일 기재 없음 / 모름. ‘기재 없음’은 영구 유효 인정이 아님 |

이름·날짜·기관은 본인 열람·수정 목적의 비공개 정보로 취급한다. 초기 상대방에게 공개하지 않는 것을 기본안으로 권고한다. 향후 공개가 필요하면 항목명·미확인 상태 등 최소 범위를 별도 승인한다. 이용목적·보관·삭제·기기 저장 안내를 제공하되 불필요한 포괄 동의를 만들지 않는다.

## 8. 건너뛰기·향후 매칭 정책 권고

모든 작업자에게 03-3 건너뛰기를 허용한다. 신규·기술작업자·장비작업자 모두 적용하며 면허가 없는 사람이 가입 자체를 못 하는 구조를 만들지 않는다. 안내: ‘나중에 등록할 수 있습니다. 법정 면허·교육 등이 필요한 작업은 해당 요건 확인 후 확정할 수 있습니다.’

| 상황 | 가입·일반 탐색 | 향후 해당 작업 매칭 |
| --- | --- | --- |
| 미등록·나중에·보유 항목 없음 | 허용. 신뢰 감점/전체 검색 배제 금지 | 법정 필수요건 작업의 자동 제안·확정 대상으로 통과시키지 않음. 본인에게 보완 경로 제공 |
| 신고만 있고 미확인 | 허용, 미확인 명시 | 공고 열람·상담은 허용 권고. 수동 지원은 확인 대기 접수 가능하되 자동매칭 적합 후보 통과·확정은 보류 |
| 입력 만료일 지남·제한 범위 불명 | 수정·보완 허용 | 해당 요건 확인 전 보류. 자동 위법/허위·귀책 판정 금지 |
| 업무에 법정 자격이 불필요하다고 검토된 경우 | 다른 직종·일정·숙련 조건 적용 | 자격 미등록만으로 배제하지 않음 |
| 어떤 법정 요건인지 자체가 조사 필요 | 공고 열람 가능 | ‘요건 검토 필요’로 해당 작업 확정 보류. 일반 이용 전면 차단 금지 |

이 표는 **후속 운영정책 권고**다. 현재 매칭 코드가 이를 수행한다고 주장하지 않는다. 검증 수단이 없는 초기에는 자격 필수 작업의 자동 확정을 열지 않는 것이 기본안이다. 업체의 ‘확인했음’ 체크나 양측 동의만으로 법정 요건을 면제하지 않는다. 운영 시작 전 검증 책임·수단·유효기간·이의제기 절차를 별도 확정한다.

작업 확정 직전에 작업일·요구 종별·제한·자격 revision·검증 근거·교육 조건을 재확인한다. 며칠짜리 작업은 전체 기간 조건을 확인한다. 확정 후 자격 변경·만료가 드러나면 재검토/당사자 안내를 설계하며 과거 계약·작업 이력을 삭제하거나 자동 취소하지 않는다. 이 예외의 상세 처리도 후속 승인 대상이다.

### 저장·복원 계약

1. 신규 전용 키 후보 `node_03_3_credentials_v1`. 계정 연동 전에는 비민감 최소 입력을 사용하는 검토용 로컬 화면으로 제한한다. 공용기기 주의·기기에 저장됨을 표시하고 사용자 명시적 임시저장 버튼을 기본으로 권고한다. 자동저장은 별도 채택 전 기본 비활성이다. 직접 입력 임시값은 메모리에서 유지하고 이동/종료에는 저장 여부를 안내한다.
2. 기존 `node_03_2_a_v1`, `node_03_2_v1`, `node_worker_v05/v04/v03`는 쓰기·삭제·이름 변경·전체 초기화 금지. 이 작업에서 실제 값은 읽지 않았다. 후속 이관도 사용자 실행으로 특정 값만 가져오는 방식이다.
3. 03-2에서 읽는 최소값은 records의 id·mode·kind 및 추천에 필요한 명시적 상태. 제조사·일련 식별정보·기타 프로필 전체를 새 상태에 복사하지 않는다. 기록 없는 초안을 운전 가능 장비로 간주하지 않는다.
4. 저장 성공 시 목록/초안/진행 상태를 한 문서로 함께 기록한다. 실패하면 메모리 입력·기존 저장 원문 유지, ‘저장되지 않았습니다’ 표시. 실패한 상태에서 다음 화면으로 이동하지 않는다.
5. 복원은 JSON 파싱뿐 아니라 버전·형식·배열·필수 식별자를 검사. 손상 또는 미래 버전은 쓰기 중지·복구 필요 표시. 자동 빈값 덮어쓰기나 구 키 fallback 금지. 알 수 없는 키/enum/명칭은 원문 보관 후 명시적 수정 전 읽기 전용.
6. 날짜 상태를 모름으로 바꿔도 기존 원문은 원본 보존 영역에 남기되 현재 유효 날짜값으로 사용하지 않는다. ‘미입력’과 명시적 ‘모름’을 구분한다. 과거 입력 오류는 새 유효값으로 승격하지 않는다.
7. 다중 탭은 revision 충돌을 감지해 저장을 중지하고 재불러오기/현재 입력 보관을 안내. 마지막 저장 우선으로 조용히 덮어쓰지 않는다. 동일 출처·원본 인덱스·지문 기반 이관 식별자로 반복 가져오기 중복 방지.
8. 구 `licenses[{title,date,verified}]`는 원문을 보존하고 ‘이전 입력·유형 확인 필요’로 미리보기. 명칭만으로 면허/기능사를 자동 분류하지 않는다. 사용자가 분류·목록 반영을 확인하기 전 추천·법정 매칭에 사용하지 않는다. `verified` 원문은 legacy 필드로만 남기고 ‘증빙 준비됨’도 미확인으로 표시한다.
9. ‘전체 초기화’가 필요하면 03-3 전용 상태만 명시적으로 대상으로 한다. 기존 화면 키까지 지우는 구 시안 reset 동작을 재사용하지 않는다.
10. 로컬 프로토타입 자료를 계정 귀속으로 추정하지 않는다. 계정 전환·로그아웃 시 자동 가져오기 금지. 실제 서버 연동은 세션의 bigint accounts.id/worker_profiles.account_id로 소유권 확인 후 별도 자격 테이블과 이관 승인 절차 설계. UUID를 기존 계정 ID로 대체 사용하지 않는다.

### 중복·삭제·개인정보 보존

같은 공식 코드+제한의 면허/자격은 중복 안내 후 기존 항목 보기·수정 경로를 제공한다. 기관·날짜가 다를 수 있으므로 자동 병합/삭제 금지. 교육은 재교육·회차가 달라 같은 이름 복수 허용하며 동일 이름·이수일·기관이면 중복 경고한다.

초안·신고 항목 삭제와 확정 거래 이력 삭제는 다르다. 초기 로컬 화면의 삭제는 본인 목록에서 제거하며, 저장되지 않은 변경을 복구용 영구 기록으로 무한 보존하지 않는다. 미래 서버에서는 수정 전 revision/관련 거래 참조 보존과 개인정보 삭제를 구분하고 법적 보존 근거·기간·접근권한·파기 절차를 승인받아야 한다. 일괄 영구 보관이나 임의 보관일수 확정 금지. 로그·분석에 자유입력 원문·번호·첨부를 남기지 않는다.

## 14. 이번 작업 확인 기록

작업 시작 시 브랜치·HEAD가 지정 기준과 일치하고 git 미커밋 변경이 없음을 확인했다. 기존 문서·코드·SQL을 정적으로 검토하고 공식 웹 자료를 조회했다. 사용자 브라우저·localStorage·DB에는 접근하지 않았다. 테스트 실행·서버 실행·마이그레이션·커밋·푸시·배포는 하지 않았다. 문서 작성 후 변경 목록과 기존 추적 파일 차이를 확인해 이 문서만 신규 파일임을 검증한다.
