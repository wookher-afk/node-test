## 재개 시 확인한 상태

10월 31일 작업은 지역·시간·달력 UI와 API 호환 처리까지 구현되어 있었다. 서버 회귀 128/128, 실제 Chrome 390/1440px 등록·수정·재로그인, 기존 DB 등록 문서 6건 보존 검증이 완료돼 있었다. 공통 분류표 감사는 완료/대기 상태이며 제품 코드는 변경하지 않았었다. 기존 미커밋 변경과 현재 브랜치를 유지했다. 이번 재개에서는 천 단위 표기를 만원 입력으로 변경하고 해당 변경에 필요한 검증을 수행했다.

## 최종 동작

- 희망 지역: 시도 → 시군구 선택 후 여러 지역 추가/삭제. 전국 및 시도 전체 지원. 시도 전체가 있으면 하위 지역 중복 추가 방지. 화면명과 함께 법정동 시도 2자리/시군구 5자리 코드를 저장한다. 전국은 애플리케이션 범위 코드 `00`이다.
- 지역 원본: 행정안전부 행정표준코드관리시스템 `https://www.code.go.kr/etc/codeFullDown.do`, 법정동코드 전체자료 2026-10-01 스냅샷. 공공누리 제1유형 출처표시. 브라우저/서버가 동일한 고정 목록을 사용한다. 세종은 원본 3611000000에서 시도 범위 36과 시군구 36110을 구성했다.
- 희망 급여: `20` 입력 → `20만원` 표시 → `minimumPayWon: 200000` 저장. 월급 `350` → `350만원` → `3500000`원. 일급·월급·기존 시급 선택을 유지했다. 화면에 천 단위 쉼표를 붙이지 않는다.
- 공통 급여 변환: 작업자와 업체 프로토타입이 같은 변환 코드를 사용한다. 기존 200001원은 `20.0001만원`으로 복원된다. 최대 소수점 4자리까지 받아 원 단위 정밀도를 보존하며 부동소수점 곱셈 반올림 대신 정수부/소수부를 분리해 변환한다. API는 기존 원 단위 정수 규약을 유지한다.
- 시간: 공통 모달에서 시·분 선택. 신규 기본 간격은 00/30분이고, 기존 08:15 등은 추가 선택값으로 유지된다. 취소/완료·키보드 초점 복원 지원. HH:mm 저장과 익일 퇴근 의미를 유지한다.
- 일정: 신규 기본은 상시 가능. 특정 날짜는 달력 입력으로 추가/삭제, 기간은 시작일·종료일을 달력으로 선택한다. 쉼표 날짜 입력은 제거했다.

## 비파괴 호환 처리

SQL 스키마 변경이나 기존 행 일괄 갱신을 하지 않았다. 기존 JSONB 문서는 GET에서 그대로 읽는다. 화면에서 기존 지역명 중 확실히 알 수 있는 값만 코드로 연결하고, 미확인 원문은 `기존 입력`으로 표시하며 `legacyRegions`에 보존한다. 저장 시 `regionCodes`, `regionCodeSystem`, `availability`를 추가한다. 기존 `regions`, `availableDates` 형식도 API가 계속 받는다.

상시·기간의 `availableDates`는 빈 배열이며 명시적 `availability`가 일정 의미를 보관한다. 특정 날짜는 두 필드가 일치하는지 API가 검증한다. 잘못된 코드·코드와 명칭 불일치·전체와 하위 지역 중복·잘못된 날짜/기간·시간/급여/우선순위·버전 충돌 검증을 유지/추가했다.

업체 프로토타입의 기존 `c_positions[].pay`는 원 단위 저장값을 유지하며 화면에서만 만원으로 변환한다. 잘못된 급여 입력은 저장하지 않고 안내하며 입력값을 유지한다. 다른 프로토타입 임시저장 데이터는 보존한다.

## 남은 문제와 미검증

1. **실DB 업체 화면에는 아직 급여/구인 입력란 자체가 없다.** 이번 업체 화면 변경은 기존 별도 프로토타입에 적용했다. 현재 업체 구인 API는 일급 전용이며 월급을 거부하는 기존 규약을 유지했다. 따라서 업체 월급의 서비스 UI→실DB 전체 연결은 완료된 것으로 볼 수 없다. 새 구인 화면·월급 DB 모델을 이번 변경에서 추가하지 않았다.
2. 실제 iOS/Android 기기와 Safari/Firefox는 미검증이다. 공통 시간 모달은 브라우저 기본 time input을 사용하지 않지만 내부 select 표시와 날짜 달력은 기기 기본 UI를 따른다. 실제 Chrome은 데스크톱 실행의 390px/1440px 뷰포트로 검증했다.
3. 행정구역 스냅샷 이후 개편의 자동 갱신, 미확인 과거 지역 원문의 자동 코드 연결은 구현하지 않았다. 미확인 원문은 보존되며 정확한 지역을 추가하고 기존 입력을 삭제할 수 있다.

자동매칭 엔진, 원격 푸시, 배포, 병합은 수행하지 않았다.
