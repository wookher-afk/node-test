# 2단계 추천: 확정 우선순위 반영

2026-11-01, `feature/node-alpha-01-worker`.

## 동작

모집항목별 실제 충족일수/요청일수 내림차순 → 업체 제시액과 작업자 희망액의 절대 차이 오름차순 → 작업자 계정 ID 오름차순이다. 같은 모집항목은 요청일수가 같으므로 정렬에서는 실제 충족일수를 비교한다. ID는 정수 문자열의 길이·사전 순으로 비교하여 bigint 정밀도를 보존한다. 입력 배열을 변경하지 않는다.

정책은 `schedule-first-price-gap-v1`, API `temporaryPolicy=false`다. 기존 응답의 `tier`와 `exactMatch`는 기존 비교조건 설명을 유지하며 정렬에 사용하지 않는다. `priorityGroup=priority:N`은 충족도와 절대 가격 차이가 같은 후보의 묶음이다. ID는 묶음 내 표시 순서를 결정한다. `position`은 모집항목마다 1부터 시작한다.

업체가 명시한 `requiredMatch`는 가격·일정을 포함하여 모두 기존 정확 비교 결과가 pass여야 한다. 이전 추천 코드가 업체 선택 가격·일정까지 무조건 완화하던 동작을 수정했다. 업체가 가격·일정을 필수로 선택하지 않은 경우에만 이들 차이를 추천에 허용한다. 기존 작업자 측 가격·일정의 추천 완화 동작은 유지했다. 그 밖의 양측 필수조건 합집합, 장비 정확 규격·옵션·경력·모집 방식·기술직 조건을 유지했다. 가격 필수의 기존 의미는 업체 제시액 ≥ 작업자 희망액이며 금액의 동일성을 새로 요구하지 않는다.

정확 매칭 계산 함수 및 auto-matches 경로는 변경하지 않았다. 추천 라우트의 정책 표시만 교체했다. 규격 불일치·누락 및 날짜 비중복은 계속 제외한다. 가격 차이 상한·최소 충족률, 일정 분할·수락·거래가격 확정·UI·스키마는 추가하지 않았다.

## 실제 API 정렬 예시

업체 미니 017, 2026-11-02~30(29일), 일급 550,000원. 가격·일정은 업체 필수로 선택하지 않았으며 다른 필수조건은 모두 충족한다.

| 순위 | 후보 | 희망 일급 | 충족일/요청일 | 절대 차이 | 묶음 |
|---|---|---:|---|---:|---|
| 1 | A | 550,000원 | 29/29 | 0원 | priority:0 |
| 2 | B | 570,000원 | 29/29 | 20,000원 | priority:1 |
| 3 | C | 550,000원 | 16/29 | 0원 | priority:2 |

C는 11/02~17 충족, 11/18~30 미충족이다. B는 가격이 달라도 전체 기간을 충족하므로 C보다 먼저다. 단위 테스트에서는 B ID 20, C ID 3으로 뒤집어도 B가 먼저임을 확인했다. 규격 020·빈 규격·12월만 가능한 후보는 제외했다.

동일 충족일수에서 +10,000원과 -10,000원은 같은 가격 차이로 취급하고 ID 순으로 표시하며, ±20,000원 후보보다 앞선다. 1일이라도 더 충족하는 후보는 훨씬 큰 가격 차이가 있어도 먼저다.

같은 API에서 업체 필수를 가격만 선택하면 A·C, 일정만 선택하면 A·B, 둘 다 선택하면 A만 남는다. 이는 필수조건을 무단 완화하지 않는 동작이다.
