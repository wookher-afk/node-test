# 운전 가능 장비 건수 조사 — 2026-11-01

## 판정과 남은 확인

사용자는 **장비 추가 직후부터 0건**이라고 확인했다. 이후 사용자가 “아니야 등록된걸 확인했어”라고 알려 정상 등록 확인으로 정리했다. 동일한 즉시 0건 증상은 독립적으로 재현하지 못했으므로 그 원인은 확정하지 않았다. 아래 수정은 조사 중 독립적으로 재현한 **서버 저장 전 재진입 시 장비 목록 소실** 문제다. 사용자가 보고한 즉시 0건 증상의 해결로 단정하지 않는다.

## 재현과 데이터 흐름

1. 별도 브라우저에서 `/worker-registration`의 장비 iframe에 접속한다.
2. 기사 유형 선택 → 운전 가능 장비 추가 → 토공·기초 → 굴착 → 굴착기 → 미니 → 008 → 장비 추가 저장.
3. 즉시 iframe의 `state.records`와 계정별 localStorage에 ability 기록 1건이 생성되고 화면은 1건이 된다. 이 버튼은 API에 요청하지 않는다.
4. 바깥 화면의 전체 등록 정보 서버 저장 전 재접속한다. 기존 부모 화면 초기화가 GET의 빈 문서로 localStorage를 무조건 덮어써서 0건으로 돌아간다. 새 회귀 테스트가 수정 전 이 지점에서 실패했다.
5. 전체 서버 저장은 iframe export → abilities/ownedEquipment 분리 → PUT `/api/me/worker-registration` → 서버 검증 → `worker_alpha_registrations.document` jsonb 저장 → GET → iframe 복원 → records 필터 건수 계산 순서다.

실제 원본 DB는 읽기 전용으로 검사했다. 운전 가능 장비가 존재하는 등록 문서들이 있으며 mode 값도 ability다. 비어 있는 문서들도 존재한다. 원본 계정에 로그인하거나 해당 계정 자료를 수정하지 않았으므로 사용자의 특정 계정에서 실제 저장이 실패했는지는 단정할 수 없다.

별도 브라우저에서 31종 중 30종의 첫 형태·첫 규격은 모두 즉시 추가됐다. 기타 장비는 필수 장비명/직접 입력 형태를 비워 검증에 걸렸다. 이 경우 목록 추가도 API 저장도 발생하지 않는다. 이는 해당 필수값을 입력하지 않은 테스트 조건의 결과이며 사용자 증상과 동일하다는 근거는 없다.

## 수정 범위

- `web/worker-registration.html`: 임시목록이 기반으로 한 서버 버전과 현재 서버 버전이 일치하면 임시목록·작성 중 입력을 복원한다. 서버 문서가 없는 기존 무버전 임시목록도 보존한다. 버전 불일치/잘못된 원문은 계정 키의 `_backup_<UUID>`에 보관한 후 서버 자료를 복원한다. 원본 일반 03-2 키는 건드리지 않는다. iframe 로드 후 선호 장비 목록도 동기화한다.
- `ui/03-2/app.js`: 서버 저장 성공 시 계정별 임시목록에 기준 서버 버전만 반영하는 ACK 함수를 추가했다.
- `tests/ui/equipment-count.test.cjs`: 가상 API 기반 재접속, 직후 건수, 기사 구분, 보유장비 분리, 수정, 저장 요청, 복원, 서버 버전 충돌 원문 보관, 손상 원문 보관, 390/1440 가로 넘침 회귀.
- `tests/ui/equipment-count-postgres.test.cjs`: 전용 폐기 DB에서 UI→임시저장→재진입→PUT→DB JSON→GET→로그아웃/로그인→건수 검증.

HTML 요소 순서·CSS·iframe 크기·장비 분류·서버 스키마는 변경하지 않았다. 상태 안내문은 임시목록 복원 상황을 알리도록 변경했다. 기존 미커밋 소스 위에서 관련 두 소스 파일만 수정했다. 이 작업의 수정분은 `app-session.patch`, `worker-session.patch`에 별도로 기록한다.

## 검증

- 전체 서버 회귀: 147/147 통과 (`server-tests.txt`).
- 신규 브라우저 회귀: 390px/1440px 통과 (`ui-regression.txt`).
- 실제 API/DB/재로그인: 390px/1440px 통과 (`postgres-tests.txt`).
- 원본 DB 보존: 57개 테이블, 시작 시점 298개 원본 행 해시 전부 동일 (`db-preservation.txt`). DB 백업 복구나 마이그레이션은 수행하지 않았다. 테스트 쓰기는 `node_test_equipment_count_20261101`에만 했다.
- 기존 UI 회귀: 15개 스위트 전부 통과 (`ui-regression-results.json`). 테스트 포트는 8054로 맞추고 산출물은 이 보고서 폴더에 분리했다. 기존 테스트 파일은 수정하지 않았다.

실제 계정의 브라우저 저장소는 읽거나 수정하지 않았다. 이미 과거에 덮어써져 소실된 임시목록을 되살린다는 의미는 아니다. 푸시·배포·병합·커밋을 하지 않았다.
