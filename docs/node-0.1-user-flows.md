## 목적·근거·상태 표현

코드·화면을 만들지 않고 [기능 목록](node-0.1-feature-inventory.md)의 후보 흐름을 정리한다. 근거는 [운영정책](operating-policies.md), [B 정책](b-policy-decisions.md), [요구사항](requirements-node-0.1.md), [신뢰정보](work-records-and-trust.md) 및 [감사](policy-consistency-audit.md)다. 각 입력은 필요한 정보의 종류이며 새 필수 입력항목 승인이나 개인정보 수집 승인이 아니다.

계정·인증, 공고, 지원, 제안 응답, 조건 버전별 양측 승인, 계약 확정, 날짜별 근무 확인, 지급 신고/수령 확인, 통계, 제출 문서 권한을 별도 상태로 다룬다. 표의 상태 이름은 이해를 위한 설계 표현이며 DB 열거값을 확정하지 않는다. 계약 서명·전자서명(DOC-002)은 매칭 확정과 별개이고 아직 상세 정책 미확정이다. W/E 식별자는 흐름 단계이며 신규 정책 번호가 아니다.

## 상태 연결의 필수 분리

1. 수락 → 미응답 종료. 계약 확정 → 동일 조건 양측 승인·최종 검증·정원/일정 잠금. 둘을 하나로 만들지 않는다(B8-11·SM-45).
2. 날짜별 근무 확인과 계약 전체 완료는 별도다. 어느 한쪽 미응답만으로 완료시키지 않는다(P-26·B7-13).
3. 지급 신고와 수령 확인도 별도다. 근무 완료가 정산 완료를 자동 확정하지 않는다(P-07·B5·SM-65).
4. 계약 확정 1건과 실제 근무일·지급 회차·금액 가중 통계를 구분한다(P-24·B7-1·5·8).
5. 알림 발송 확정, 채널 성공, 전체 안내 완료, 실제 기기 도달, 열람, 신고 공식 통지를 구분한다(B8-70·71·SM-54·55·61~64).
6. 문서 본문·발급·제출·열람 이력·접근 권한·최소 진위정보는 독립 관리한다(P-39~50·SM-74~76).

## 장비·운송 연계 시 추가 흐름

작업자가 장비를 공급한다면 소유/관리/기사 권한·장비 가용을 먼저 확인하고 작업자와 장비 모두 예약이 가능해야 확정한다(EQUIP-001~005). 고장 시 대체 장비의 신규 조건·당사자를 재승인한다(EQUIP-009). 업체 또는 공급자가 운송을 요청한다면 운송비 부담자 동의 → 차량 적재능력·일정 확인 → 운송업자 최종 확인 → 인도 신고·인수 확인 → 운송비 지급/수령을 별도 의무로 대사한다(LOG-001~006). 업체·장비 소유자·운송업자를 하나의 계정/계약 당사자로 추정하지 않는다. 해당 흐름을 0.1에 포함할지는 C16의 결정 대기다.

## 남은 작업

[후속 결정 기록](policy-followup-decisions.md)의 C01~C04 기확정 기준과 C05~C14 위임 운영 기준을 적용한다. 요금표·제재 수위·법적 보존기간과 근거·분야별 법정 자격 목록은 별도 검토 필요다. 이러한 값을 임의로 채우지 않는다. C15 아이디어와 C16의 직종·지역·일정 단위·수동/자동·장비/운송·무료/유료 제공 범위는 추천 상태이며 사용자 범위 승인 전 확정하지 않는다. 각 입력·상태·권한·예외의 상세 명세는 D 항목으로 진행할 수 있다. 본 문서는 구현 승인이 아니다.
