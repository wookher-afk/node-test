## 목적·판단 방법

확정 정책과 요구사항의 모든 주요 기능군을 목록화한다. 분류는 개발 우선순위 권고이며 **0.1 범위 최종 확정이나 기존 기능 삭제가 아니다**. F01 등은 이 문서의 기능 추적 식별자이며 신규 정책 번호가 아니다. 정책은 확정돼도 후속 제공 후보일 수 있고, 개인정보 보호·취소·기록 보존처럼 제공 기능의 필수 안전장치는 후순위로 미룰 수 없다.

근거: [헌법](NODE-CONSTITUTION.md), [운영정책](operating-policies.md), [B 정책](b-policy-decisions.md), [요구사항](requirements-node-0.1.md), [신뢰정보](work-records-and-trust.md), [통합 매칭](matching-implementation.md), [DB 설명](../database/README.md), [안정화](stabilization-1.md), [감사 분류](policy-consistency-audit.md). 계정·현장·장비·운송 전용 문서가 없는 항목은 요구사항의 해당 확정 ID를 근거로 했다.

| 분류 | 의미 |
| --- | --- |
| 핵심 후보 | 첫 실제 작업자↔업체 거래 흐름과 필수 예외·보호 처리에 필요 |
| 후속 후보 | 초기 사용 후 단계적으로 추가 가능한 제공 기능. 정책 확정을 취소하는 뜻 아님 |
| 공통 기반 | 여러 제공 기능이 공유하는 계정·권한·기록·개인정보·자원 보호 |
| 사업 결정 대기 | 요금·제재·법률·미확정 아이디어·초기 범위의 별도 의사결정이 필요 |

범위가 ‘장비+기사’ 현장으로 선택되면 F44~F48은 핵심 후보로 재분류해야 한다. 운송까지 거래에 필수라면 F49~F51도 함께 재검토한다. 현재 분류를 이유로 사용자가 필수인 장비·운송 확인을 우회하지 않는다.

## 분류 집계와 첫 이용 흐름 후보

| 분류 | 기능 묶음 수 |
| --- | --- |
| 핵심 후보 | 25 |
| 후속 후보 | 20 |
| 공통 기반 | 10 |
| 사업 결정 대기 | 7 |

이는 62개 기능 묶음의 분류이며 정책 230건의 분류 개수와 다르다. 첫 흐름 후보는 계정·업체/현장·작업자 프로필 → 공고와 지급 조건 → 명시적 일정 → 검색/지원·직접 제안 → 동일 조건 양측 승인·일정 잠금 → 일별 근무/계약 완료 확인 → 지급 신고·수령 확인 → 독립 신뢰지표 반영이다. 취소·우천·이견·직접 제외·신고 보호·탈퇴·자료 보존은 예외 경로로 함께 설계한다.

자동 후보 탐색과 추천 정밀화는 후속 후보로 제시했지만, 자동 모드·알림 정책 자체의 제공 시점은 C16의 사용자 결정이다. 수동 흐름을 채택하더라도 충돌·정원·동의·접근 보호는 유지해야 한다. 요금 미정 상태를 무료로 확정하거나 모든 확정 정책을 0.1 동시 개발 대상으로 간주하지 않는다.

## 포함하지 않는 임의 확장

P-07의 NODE 대금 보관/송금, P-13 초기 별점, P-27 GPS 인증 제외, B7-21 종합 신뢰점수 금지는 유지한다. 주관 평가 테이블이나 학습 동의 기록이 있다는 이유로 별점 공개·학습 모델·학습 데이터 내보내기를 구현 확정 목록으로 넣지 않는다. 전자서명과 일반 서류 전달은 미확정 아이디어로 구분했다.

## 남은 작업

사용자는 C16에서 첫 대상 직종·일정 단위·장비/운송 필요·제공 기능·요금 및 운영 인력을 결정한다. 이후 C01~C15 중 채택 기능의 선행 결정과 D01~D12를 연결해 세부 설계한다. 설계 초안은 [이용 흐름](node-0.1-user-flows.md), 게이트는 [설계 준비 보고서](node-0.1-design-readiness.md)를 따른다. 이번 목록은 개발 승인이나 완료 표시가 아니다.
