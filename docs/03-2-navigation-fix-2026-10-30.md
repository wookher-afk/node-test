# 03-2 → 03-3 긴급 이동 수정 (2026-10-30)

## 재현 및 원인

- 수정 전 `move('next')`는 기사 유형 선택·장비 1건 이상·저장 성공 후에도 `review.hidden=false`만 실행했다. 실제 URL 이동은 검토 영역의 별도 링크를 한 번 더 눌러야 했다. 격리 브라우저에 수정 전 핸들러를 제공하여 URL은 03-2, 검토 영역은 표시되는 상태를 재현했다.
- 이 채팅에서 연 실제 8033 브라우저에서는 기사 유형 미선택·장비 0건이었다. 다음 버튼 클릭 시 “기사 유형을 선택하고 장비를 하나 이상 목록에 추가하세요.”가 표시되는 차단을 수동 재현했다. 이는 일반 기사 경로의 기존 필수 조건으로 유지한다. 과거 보고 당시의 다른 브라우저 저장 상태까지 확인한 것은 아니다.
- 기술작업자 링크는 위 조건 없이 같은 출처의 `../03-3/`로 이동한다. 실제 클릭하여 03-3 제목과 기존 면허 기록 표시를 확인했다. 기록을 추가·수정·삭제하지 않았다.
- 실제 127.0.0.1:8033 서버의 `/ui/03-3/`는 HTTP 200. 현재 서버는 Python 정적 서버이며, 이번 문제에 서버 라우팅 변경은 필요하지 않았다.

- `ui/03-2/index.html`: app.js 조회 버전 변경으로 기존 캐시와 구분. 기존 미커밋 03-3 링크 구현은 보존.

- `tests/ui/03-2.test.cjs`, `03-2-a.test.cjs`, `03-2-flow.test.cjs`: 종전 검토 영역 기대값을 실제 03-3 이동으로 갱신하고 시험 라우팅 확장.
