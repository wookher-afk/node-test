# NODE 0.1 — 확정 요구사항 기준서
상태: 설계 기준선 초안 / 구현은 단계별 진행. 이 문서는 확정된 정책을 추적하며, 상세 필드 및 운영 파라미터는 별도 검토 대상이다.

## 상위 원칙
- UX-001: 내부 복잡성은 NODE가 처리하며 사용자에게는 필요한 결정만 노출한다.
- 일의 기록 = 신뢰. 신고/미응답/분쟁 제기 자체를 자동 불이익으로 취급하지 않는다.
- 매칭 확정은 양측의 동일 조건 승인; 계약 서명, 작업 완료, 지급 완료는 별도 상태.
- 공개 저장소에 실명, 연락처, 계좌번호, 신분증, 비밀키, 실제 개인정보를 저장하지 않는다.

## 근무 기록 (확정 정책, 구현은 후속)

- WRK-003 P-26~30에 따라 날짜별 근무 완료는 양측이 확인한다. 출퇴근과 실제 작업시간을 구분하고 시간 입력은 선택사항이며 일치한 작업시간만 확정한다. 다중 날짜 일괄 입력·확인을 지원한다. 미응답은 자동 승인 없이 확인 대기로 유지하고 재알림한다.
- 작업자 본인과 해당 현장의 확인 권한이 있는 업체 담당자가 확인하며 권한 없는 직원의 확정·변경을 금지한다. 확인·변경자와 처리 시각, 담당자 변경 전후 기존 이력을 보존한다.
- GPS 위치 추적·위치 기반 출퇴근 인증은 제외한다. 향후 초과근무·급여 정산 기초자료 활용은 P-27을 따르며 급여 정산 기능 구현 완료를 뜻하지 않는다.

## 2026-10-27 운영정책 등록

[운영정책](operating-policies.md)의 P-01~P-50과 [결정 이력](policy-decision-log.md)을 함께 따른다.
P-01·07 지급 조건, P-02 마감, P-03~05 취소·보상, P-06 완료, P-08~09 분쟁, P-10~19 통계·공개·선택·필터를 추적한다.
정책 문서 등록과 DB/API/UI/테스트/배포 완료는 별개다. 기존 구현 추적표는 기존 기반의 상태이며 P-03 등의 신규 정책 구현 완료를 뜻하지 않는다.
WRK-003의 기존 일방별 확인 구상은 P-26~30으로 대체한다. 근무일 완료와 선택적 시간 확인, 계약 전체 완료는 구분한다.

P-20·21은 거래 기록 없음/산정 불가, 거래 건수·비율 동시 표시 및 확정 매칭 5건 미만 기록 적음 안내를 규정한다.
P-22·23에 따라 확정 이벤트와 정정 결과로 통계를 갱신·재계산하고 지연 시 마지막 갱신 시각을 표시하며 정정 이력을 보존한다.
P-24~26에 따라 확정 매칭 계약 1건과 실제 근무일수를 분리한다. 중도 종료 사유를 분류하고 실제 근무 이력은 보존하며 확정 귀책만 취소 통계에 반영한다. 날짜별 이견은 해당 날짜만 분쟁으로 관리한다.
근무 확인 기한은 P-31, 담당자 관리 원칙은 P-33으로 확정한다. 재알림 반복·통합의 구현 방식, 세부 권한 운영 절차, 귀책 인정 절차와 통계의 미확정 세부 산식은 후속 검토한다.

## P-31~P-40 근무 기록 후속 요구사항 (정책 확정, 구현은 후속)

- P-29·31: 최초 요청 후 24시간 재알림, 72시간 미응답 시 장기 확인 대기. 자동 승인·미응답 불이익 없이 언제든 확인/이의 제기가 가능하며 장기 대기 건수는 본인에게만 표시하고 공개 신뢰 통계에서 제외한다.
- P-23·32: 확정 근무 기록의 당사자 정정은 상대방 승인 절차를 따른다. 거부 시 기존 기록을 유지하고 이의 제기로 관리하며 전후 내용·처리 이력을 보존한다. 시스템 자체 오류는 운영자 확인 후 정정할 수 있다. NODE의 거래 분쟁 귀책 판정 금지는 유지한다.
- P-30·33: 현장별 복수 확인 담당자, 퇴사·권한 상실 시 회수, 신규 담당자의 미확인 기록 처리를 지원하고 기존 처리자 이력을 유지한다.
- P-28·34·35: 업체는 여러 작업자, 작업자는 자신의 여러 날짜를 일괄 확인한다. 사전 대상·날짜·건수 표시, 분쟁/이의 기록 제외, 개별 확인자·시각 보존을 따른다. 동일 현장 요청은 통합하고 분쟁/이의 알림은 구분하며 작업자에게도 같은 통합 원칙을 적용한다.
- P-16·36·38: 개별 기록의 기본 비공개와 확정 범위의 통계 공개를 유지한다. 작업자 본인 전체 열람, 업체의 현장별 열람 권한, 정당한 운영자 접근과 접근 이력을 구분한다. P-38은 작업자가 선택하여 직접 제출한 범위에 한해 수신 업체가 열람하는 경로이며 원본 수정이나 미제출 상세 기록 공개를 허용하지 않는다.
- P-37~40: 선택한 본인 이력을 상태 구분·발급일과 함께 PDF/엑셀로 출력하고 다른 작업자 개인정보를 제외한다. 제출 범위·수신 업체·시각을 기록하고 고유 확인번호 또는 QR로 발급·위변조 및 NODE 기록과의 일치 여부를 확인한다. 이는 법적 증명·실제 근무의 법적 보증이 아니다. 정정 시 기존 발급 문서의 변경 사실을 표시하며, 철회 즉시 NODE 내 열람을 중단한다. 이미 외부에 보관된 문서의 회수 불가를 사전 안내하고 원본 삭제·법령상 보존과 구분한다.

일반 민감 서류 전달(DOC-001)의 미확정 상태는 유지하며, P-37~40의 본인 근무 이력 출력·제출 범위와 구분한다. 구현 추적표는 기존 DB 기반의 상태이며 이번 정책의 구현 완료를 뜻하지 않는다.

## P-41~P-50 제출 문서 요구사항 (정책 확정, 기능 구현 승인 아님)

P-37~40의 본인 이력 출력·직접 제출·진위 확인·철회를 구체화하며 DB-005의 권한 감사, DB-014의 상세 기록과 공개 통계 분리 원칙에 연결한다. 일반 민감 서류 전달 DOC-001 전체를 확정하는 것으로 확대하지 않는다.

- P-38·40·41·50: 제출 시 7일/30일/90일을 선택하고 만료 시 열람을 자동 종료한다. 만료 전 조기 철회가 가능하다. 유효한 문서의 연장은 수신 업체 요청과 작업자 승인·새 기간 선택을 따르며 미승인 시 기존 만료일을 유지한다. 만료·철회 문서는 연장하지 않고 새로 제출한다. 원본·제출 이력 보존과 다운로드 사본 회수 불가 원칙을 유지한다.
- P-36·38·42: 수신 업체에서도 권한 있는 채용·인력관리 담당자만 제출 문서를 열람한다. 일반 직원은 제외하며 퇴사·권한 상실 시 즉시 종료하고 열람자·시각을 기록한다. 문서 유효기간과 철회 제한을 함께 적용한다.
- P-43·46·50: 이름·연락처·거주 지역은 각각 선택 공개하고 근무 이력 핵심 정보는 유지한다. 제출 전 실제 표시 내용을 미리 확인하며 미승인 정보는 공개하지 않는다. 확대는 별도 동의가 필요하고 재제출 시 다시 선택한다. 연장은 내용·공개 범위를 변경하지 않는다.
- P-44·49: 제출 내역의 열람 가능/기간 만료/권한 철회 관리와 미열람/열람 완료/기간 만료/권한 철회 상태 표시를 연결한다. 수신 업체·제출일·공개 정보·유효기간·현재 상태와 업체별 열람 기록을 본인이 확인한다. 최초 열람 시각은 반복 열람에도 유지하고 철회 후 제출 이력도 보존한다. 상태가 겹칠 때의 표시 우선순위와 내부 상태 구조는 미확정으로 남긴다.
- P-45·48: 제출·열람 알림과 동일 업체의 제출 알림 통합을 적용한다. 제출 알림에는 제출자·유효기간을 표시한다. 만료 24시간 전 업체 담당자와 작업자에게 알리되 이미 열람했거나 철회된 문서는 제외한다. 만료 시 권한 종료 자체는 유지한다.
- P-39·46·47: 근무 기록 원본과 발급 당시 고정된 제출 문서를 구분한다. 추가 근무 기록은 재제출로만 제공하며 별도 발급번호·권한을 부여하고 기존 문서를 자동 삭제·변경하지 않는다. 원본 정정 시 변경 사실을 표시하되 기존 문서 본문을 자동 변경하지 않는다. P-47의 기존 기간·권한 유지는 내용 추가·정정에 의한 자동 변경 금지이며 P-40·41·42·50의 철회·만료·권한 종료·승인 연장과 함께 적용한다.
- P-39·40: 진위 확인은 NODE 기록과 문서의 일치 여부 확인이며 실제 근무의 법적 보증이 아니다. 철회 즉시 NODE 내 열람을 중단하고 다운로드 사본은 회수할 수 없다. 철회·만료 후 진위 확인의 노출 범위와 정정 표시 전달 방식은 후속 검토한다.

미열람·만료·열람 연장 등 제출 문서 관련 행위만으로 불이익이나 신뢰 통계상 감점을 부과하지 않는다. P-22~24의 객관적 거래 기록 통계 원칙은 유지한다. 이번 등록은 문서화이며 API/UI·DB·알림·접근 제어 기능 구현 승인을 의미하지 않는다.

### 미확정 구현·운영 사항

- 연장 승인 시 새 기간의 기산점·만료 시각 계산 및 시간대 처리.
- 미열람/열람 완료와 기간 만료/권한 철회가 겹칠 때의 표시 우선순위·내부 상태 구조.
- 개인정보 선택 공개 시 제출자 알림의 식별 표시 방식, 알림 통합·재발송의 세부 기준.
- 정정 사실의 기존 발급 문서 표시·전달 방식과 만료·철회 후 진위 확인의 노출 범위.
- 담당자 권한 부여·회수의 구현 방식 및 원본·제출·열람·연장 이력의 보존 기간과 법령상 처리 세부 기준.


## 2026-10-28 B 정책 연결 및 충돌 5건 정정 (정책 확정, 구현 승인 아님)

[B 정책 73개](b-policy-decisions.md)와 [결정 이력](policy-decision-log.md)의 2026-10-28 확정을 함께 따른다. P-01~P-50과 B1~B6·B7-1~21·B8-1~46의 번호를 유지하며 B8-47은 미확정이다.

- P-15·16 / B7-17: 업체 선정 전 신뢰 통계를 제공하며 자동매칭 추천 작업자의 계약 완료율도 계약 확정 전에 확인할 수 있다. 개인별 상세 근무 기록·분쟁 내용은 이 공개에서 제외한다. 상세 기록의 별도 열람·본인 제출은 P-36·38을 따른다. 무이력만으로 자동매칭에서 제외하지 않는다.
- P-03 / B8-30 / JOB-009: 감원은 미충원 인원·신규 제안에 우선 반영한다. 정원 변경만으로 확정 계약을 자동 취소하지 않으며 확정 인원 미만 축소는 별도 계약 취소 절차와 기존 귀책·보상 정책을 따른다. 최근 확정 계약부터 자동 취소하는 규정은 폐기했다.
- P-05 / B4: 작업자 귀책 확정 시 매칭권 1회 차감, 잔액 부족은 현금 채무 없는 차감 대기로 처리한다. 업체에는 대체 작업자 또는 다음 구인 건 수수료 1회 면제를 제공하며 매칭권을 대체 작업자에게 직접 지급하지 않는다. 긴급 공고 상위 노출은 유지한다. B4의 선부담·이월·정정 원칙도 유지한다.
- P-07·12 / B5·B7-1: 약정일·실제 지급일 원본을 보존한다. 실제 정시 지급률은 약정일까지 지급된 확인 금액을 기준으로, 인정 반영 정시 지급률은 여기에 작업자가 인정한 지연 수령액을 더해 산정한다. 공통 분모와 산정 대상은 B7-1·2를 따르며 두 지표를 구분해 표시한다. 인정은 실제 지급일을 바꾸지 않고 인정 후 30일 이내 철회·관련 통계 재계산을 허용한다.
- P-20 / B8-3·6·18: 기본 검색·자동매칭에서 신규·무이력 불이익을 주지 않는다. 자동매칭은 적합도 우선·신뢰 보조이며 사용자가 직접 신뢰지표 정렬을 선택한 경우에만 무기록 회원을 뒤에 표시할 수 있다. 이는 감점·이용 제한이 아니다.

B 정책 확정은 설계·DB·API·UI·검증·배포 완료와 별개다. 기존 구현 추적표와 데이터 기반 설명은 현재 구현 범위를 설명하며 이번 문서 정정으로 구현 상태를 올리지 않는다.
통계 기간 경계·시간대, 수수료 금액, 관계 종료 후 열람 범위, 세부 접근권한·보존 기간, 무기록 표시 문구·소표본 단위 및 지표별 정렬·필터 방향 등 이번에 확정하지 않은 세부 사항은 미확정으로 유지한다.
