# NODE 0.1 — 확정 요구사항 기준서
상태: 설계 기준선 초안 / 구현은 단계별 진행. 이 문서는 확정된 정책을 추적하며, 상세 필드 및 운영 파라미터는 별도 검토 대상이다.

## 상위 원칙
- UX-001: 내부 복잡성은 NODE가 처리하며 사용자에게는 필요한 결정만 노출한다.
- 일의 기록 = 신뢰. 신고/미응답/분쟁 제기 자체를 자동 불이익으로 취급하지 않는다.
- 매칭 확정은 양측의 동일 조건 승인; 계약 서명, 작업 완료, 지급 완료는 별도 상태.
- 공개 저장소에 실명, 연락처, 계좌번호, 신분증, 비밀키, 실제 개인정보를 저장하지 않는다.

## DB 기본 구조 (확정)
- DB-001 하나의 계정에 작업자·업체 역할 병존, 여러 업체 소속 가능
- DB-002 역할 점진적 추가
- DB-003 휴대전화 본인확인 및 카카오/네이버/애플 로그인 연계; 번호 변경에도 계정 유지; 민감행위 재인증
- DB-004 업체 관리자의 직원 초대, 각자 독립 계정, 복수 업체 소속
- DB-005 업체별 세부 권한, 권한 변경 감사 기록
- DB-006 현장 하나에 직종·장비·단가·기간별 복수 모집 항목
- DB-007 NODE 확정 작업·외부 작업·휴가·개인 일정 통합
- DB-008 기본 근무 요일과 일정/예외를 이용한 가능일 산출; 빈 일정은 자동 가능 판정 아님
- DB-009 동일 조건 양측 승인 및 변경 시 재승인
- DB-010 취소 주체·시점·사유 기록, 초기 자동 신뢰도 감점 없음
- DB-011 기사만/장비+기사/장비만 구분
- DB-012 작업 완료는 작업자·업체 각각 확인, 이견 및 정정 기록
- DB-013 지급자 지급 등록 + 수령자 입금 확인, 부분/지연/분쟁/미확인 구분
- DB-014 상대 매칭 검토 단계에서 신뢰정보 열람, 전체 공개 금지; 표본수/기간/이의절차

## EQUIP 장비 (확정)
- EQUIP-001 개인/법인 소유, 소유자·관리자·기사 분리, 기간별 다수 기사
- EQUIP-002 기사·장비 작업 이력 별도 집계, 원본 작업기록 공유, 소유권 이전에도 이력 유지
- EQUIP-003 장비 등록번호/권한 검증 및 고유 NODE ID; 번호 없는 장비 예외
- EQUIP-004 장비별 작업·정비·불가 일정, 장비+기사 동시 가용성 검사
- EQUIP-005 표준 종류/급수/옵션 + 사용자 제안 옵션; 설치/보유/불가 구분
- EQUIP-006 행정구역 및 보관지 기준 도로거리, 운송비/원거리 조건
- EQUIP-007 자가/업체/외부 운송, 주선자와 비용 부담자 구분, 왕복/상하차/복귀 비용
- EQUIP-008 정비·고장·수리·증빙·복귀, 자가 신고와 검증 구분, 일정 연동
- EQUIP-009 매칭 후 고장 시 대체 장비 우선 탐색, 신규 당사자 재승인, 실패 시 취소 이력 보존

## LOG 운송 (확정)
- LOG-001 장비 공급자·현장 업체 양측 운송 요청; 중복 예약 방지, 지급 책임자 동의
- LOG-002 운송업자 인도 신고 + 장비 인수자 수령 확인, 별도 시간 기록 및 이견
- LOG-003 DB-013 공통 지급 시스템 재사용, 운송비 부담자별 지급 의무 구분
- LOG-004 운송차량별 독립 운행·정비·예약 일정 및 중복 차단
- LOG-005 장비 중량/치수와 차량 적재능력/규격 사전 비교, 최종 운송업자 확인
- LOG-006 사고/지연 신고, 당사자 알림, 필요 시 대체 운송 재매칭 및 새 조건 승인

## JOB 구인 (확정)
- JOB-002 직종별 정원형 모집, 날짜별 잔여 정원 자동 계산
- JOB-003 신호수·보조인력 등 복수 직종 등록; 직종별 경력·자격·교육 구분, 직종 코드 확장
- JOB-004 동일 날짜 복수 지원 가능, 매칭 확정 시 겹치는 다른 지원의 확정 차단; 지원 이력 유지
- JOB-005 작업자 지원 및 업체 직접 제안 양방향, 연락처 비동의 공개 금지
- JOB-006 업체의 작업자 검색 기본 종합 적합도순, 거리·경력 등 정렬 가능
- JOB-007 작업자의 공고 검색 기본 맞춤 적합도순, 최신·거리·단가 정렬 가능
- JOB-008 부분 일정 지원 가능, 업체가 부분 지원 허용 여부 지정, 날짜별 정원
- JOB-009 모집 인원 증감 허용, 기존 확정 매칭 자동 취소 불가, 변경 이력
- JOB-010 전체 공개/지정 작업자 공개/비공개 직접 제안
- JOB-011 정원·지원 마감·작업일 경과 시 자동 마감, 조기 마감/재공고, 부분일정 예외
- JOB-012 선정/대기/미선정/철회 구분, 결원 시 대기자 재제안 및 재승인
- JOB-013 긴급 구인 적합자 우선 알림, 수신 동의 및 미응답 무감점
- JOB-014 긴급 알림 근거리 우선, 미충원 시 최대 허용범위 내 단계적 확대
- JOB-015 긴급 제안 응답 기한 및 자동 만료, 재제안, 미응답 무감점
- JOB-016 공고 조건 변경 이력/기존 지원자 알림, 확정 매칭 변경 시 재승인
- JOB-017 확정 전 작업자 자유 지원 철회, 확정 후 DB-010
- JOB-018 확정 전 업체 자유 제안 철회, 확정 후 DB-010
- JOB-019 거래 이력 기반 재고용·즐겨찾기, 새 일정·조건 재확인
- JOB-020 작업자·업체 상호 차단, 비공개, 기존 계약/지급 기록 보존, 자동 감점 없음
- JOB-021 양측 신고·증빙·관리자 검토·소명·처리·이의신청; 접수만으로 불이익 없음

## 추가 기능 아이디어 (확정 범위와 구분)
- JOB-001 유류 공급 주체에 따라 **계약 단가 자체가 달라질 수 있음**; 지원조건·교통/숙박/식사/운송비 구분. 상세 정책 추가 검토
- DOC-001 자격/계좌 등 민감 서류의 동의 기반 안전 전달 및 접근 로그: 세부 정책 미확정
- DOC-002 계약서 자동 생성/전자서명: 세부 정책 미확정
- WRK-001 건설기계 안전교육 유효기간/알림: 세부 정책 미확정
- WRK-003 출근은 업체 확인, 종료/연장은 작업자 확인; 출근율과 업체 평균 초과근무 등 **신뢰정보**용, 급여 산정과 별개: 세부 정책 미확정
- ADM-001 관리자 단계별 제재 방식: 아직 미확정

## 구현 추적 원칙
각 ID는 설계/DB 구현/API/UI/테스트 상태를 개별 추적한다. 확정된 정책을 구현 완료로 표시하지 않는다.
모든 신규 확정 사항은 이 파일에 반영하고, 회귀 테스트를 연결한다.

## 일의 기록 = 신뢰: 데이터 축적 기준

- TRUST-DATA-001: 객관적 활동 관측/확인, 거래 이력, 주관적 평가를 구분한다.
- TRUST-DATA-002: 신뢰·선호·작업 적합도를 별개 축으로 유지하며 이번 단계에서 점수/모델을 만들지 않는다.
- TRUST-DATA-003: 표본 수·기간·확인 수준을 보존하고, 신규/기록 부족을 낮은 신뢰로 간주하지 않는다.
- TRUST-DATA-004: 양방향 추천의 실제 노출·조회·지원·선정·거절·매칭 결과와 당시 조건 버전을 기록한다.
- TRUST-DATA-005: 원본·보고자·발생/기록 시각·독립 확인·사건·정정 계보를 보존한다.
- TRUST-DATA-006: 목적별 최소 수집, 명시적 학습 동의/철회, 평가 소명·정정·재심을 지원한다.

DB 기반은 `004_work_records_and_matching_data.sql`, 상세 정책은
[work-records-and-trust.md](work-records-and-trust.md)를 따른다.
출퇴근·지급·평가 수집 API/UI, 자동 점수·학습·추천 순위·개인정보 보존 기간 집행은 미구현이다.
