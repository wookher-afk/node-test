## 판단

**공통 기반과 사용자 흐름의 설계 초안은 착수 가능하다. 전체 정책 정합성 완결·0.1 범위 최종 확정·구현·운영 공개 준비 완료는 아니다.** 미해결 충돌은 표본 산정의 실질 상충 1건과 0건 표시의 표현 상충 1건, 총 2개 묶음이다. 철회·만료 문서 검증 권한 등 미정 운영 결정은 충돌과 별도 집계한다.

검토 기준 HEAD는 최근 검증 커밋과 일치해 이후 변경은 없었다. [감사 보고서](policy-consistency-audit.md)는 230건별 근거와 A/B/C/D 분류를, [기능 목록](node-0.1-feature-inventory.md)은 62개 후보 묶음을, [이용 흐름](node-0.1-user-flows.md)은 양측 입력·승인·상태·예외를 제공한다. 이는 권고 문서의 작성 완료이며 사용자의 정책 승인이나 개발 허가를 대신하지 않는다.

- P-01~P-50 50건, B1~B6·B7-1~21·B8-1~76 103건, SM-01~SM-77 77건, 총 230건이다. 번호 누락·중복은 없다.
- 기준 원문에서 실제 등록되지 않은 B14 참조 1종(B7-17)이 있다. 후속 번호를 새로 만들지 않고 감사 B01/C12에 연결했다.
- 감원·보상·지급 지표 분리·선정 전 신뢰 공개·신고 보호 경계, 일정 모드·휴무 예외·기한 중첩, 알림 통합·채널 성공·ID 재시도, 문서 연장 기산점은 후속 확정으로 해결됐다. 과거 ‘미결’ 표시는 A01~A22에서 현재 기준과 연결했으므로 재결정 목록에 중복 집계하지 않는다.
- 기본 회원 기능과 통합 매칭·기록 기반이 문서상 존재하지만 전체 서비스 API/UI·신뢰 통계·알림·서류·장비만 공급·운송은 완료 상태가 아니다. 현재 운영 환경 상태나 전체 테스트를 이번에 검증했다고 주장하지 않는다.

## 먼저 사용자에게 제시할 결정 세 묶음

### 1. 표본 기준(C01)

권고안은 지표별 산정 가능 기록 0건이면 산정 불가, 1건 이상 실제 비율, 1~4건 기록 적음이다. 계정 전체 거래 이력이 없는 경우 거래 기록 없음을 별도 표시한다. P-21·B7과의 정합성이 좋지만 SM-67의 ‘부족’ 적용 범위를 승인해야 한다. 금액 가중 지급률의 표본은 지급 회차, 완료/이행률은 산정 계약, 취소율은 확정 매칭 계약이다. 모든 지표를 하나의 계약 수로 통일하지 않는다.

### 2. 표시 문구(C02)

권고안은 ‘거래 기록 없음’을 계정 이력, ‘산정 불가’를 숫자 산출 여부, ‘산정 기록 없음’을 그 사유, ‘기록 적음’을 산출된 비율의 표본 경고로 분리하는 것이다. 문구 병기 또는 대표 문구 통일은 기존 원문을 바꾸므로 자동 확정하지 않는다. 0%·0점으로 대체하지 않는다.

### 3. 철회·만료 문서 진위 권한(C03)

본인과 이전 정당한 제출 관계가 있고 현재 권한을 가진 수신 담당자만 최소 검증하도록 하는 안을 권고한다. 철회·만료 후 상세 내용은 계속 금지하고, 확인번호만 가진 불특정 조회는 제한하며 접근 이력을 남긴다. 퇴사자·권한 상실자·재가입자의 권한 및 허용 기간은 별도 결정해야 한다. 최소 메타정보 제공이라는 SM-76 확정을 조회자 전체 공개로 확대하지 않는다.

## 승인된 정책만으로 시작할 수 있는 기술 설계

1. D01·D02: 계정·업체·소속·현장·작업자·장비·차량의 독립 식별과 당사자 스냅샷, 세션 기반 행위자·권한·로그의 명세 초안.
2. D04·D09·D11: 명시적 가능일/반복 휴무/개별 제외·확정 예약·관계별 차단과 신고 중지·제안 유효성의 합성. SM-12의 기한과 신규 제안 재개 조건 분리.
3. D01·D05·D08: 지원·수락·선정·양측 승인·확정·일별 완료·계약 완료·지급 신고·수령 확인·분쟁/정정 상태를 독립 관리하는 명세.
4. D03: 알림 대상/내용/ID·버전·채널 결과·전체 안내·마지막 성공 상태·대기/폐기/확인 불가의 구조. 공식 신고 통지는 내부 등록 기준, 일정 알림은 채널 성공 기준이라는 유형 분리.
5. D06·D07: 지표 정의와 권한 정책이 필요한 부분은 미결 참조로 남긴 채 원본/파생 통계·고정 발급문서/제출/열람·권한 이력 구조를 설계한다. C01·C03 값 없이 임의 산식·권한을 채우지 않는다.
6. D10·D12: 정책/요구사항별 기반·API·UI·테스트·운영 적용 상태표와 데이터 보존·검증 계획. 기존 DB를 초기화하거나 적용하지 않는다.

## 핵심 흐름 후보와 의존성

F01~F04·F20·F31·F35·F54·F55·F61의 공통 기반을 바탕으로, F05~F14 프로필/업체/현장/조건/일정 → F16~F21 지원/제안/확정/변경 → F24·F26~F29 취소·근무·완료 → F32·F33 지급·신뢰 기록 흐름이 첫 실제 사용의 핵심 후보이다. F30·F36~F39의 제외·신고·탈퇴 예외도 필요한 최소 운영 경로로 함께 설계한다.

장비 의존 작업이면 F44~F48, 운송이 필요한 계약이면 F49~F51을 후속이라고 가정한 채 출시할 수 없다. 사용자가 C16에서 범위를 정한 후 의존성에 따라 핵심으로 승격한다. 요금 미정은 무료 승인으로 간주하지 않으며 신고 제재 수준·보존기간 미정 상태에서 실데이터 수집/운영을 완료로 선언하지 않는다.

## 남은 작업과 완료 정의

이번 완료는 4개 신규 문서 작성, 230건 전수 확인표, 해결된 과거 항목 분리, C/D 분류, 기능/흐름 초안 및 브랜치 문서 커밋이다. 다음 단계의 완료는 사용자의 범위·정책 선택, 각 기능의 상태/권한/입력/예외 명세, 기존 기반 영향 검토, 별도 구현 승인과 검증이다. 기존 정책 원문·결정 이력·코드·DB·API·UI·배포·main은 이번에 바꾸지 않는다.
