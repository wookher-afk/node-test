## 판단과 검토 근거

**확정된 운영 기준으로 상태·권한·데이터·예외 설계는 착수 가능하다. 0.1 기능 범위와 법률·금액·제재 수치는 미확정이므로 전체 상세 설계 완료·운영 공개 준비 완료로 선언하지 않는다.** 사용자가 남은 감사 쟁점을 권고안대로 처리하도록 위임한 이번 지시에 따라 C05~C14의 운영 기준을 새 결정 기록으로 남겼다. C01~C04는 기확정 유지, C15·C16은 명시적 범위 승인 없이 기능으로 확정하지 않는다.

근거는 [원 정책](operating-policies.md), [B 정책](b-policy-decisions.md), [기존 결정 이력](policy-decision-log.md), [요구사항](requirements-node-0.1.md), [신뢰정보](work-records-and-trust.md), [헌법](NODE-CONSTITUTION.md), [감사 전수표](policy-consistency-audit.md), [후속 결정 기록](policy-followup-decisions.md)이다. 이번 후속 기록이 기존 정책 원문·역사를 삭제하지 않는다.

## 검증된 기준과 결정 상태

- 원 정책은 P 50건 + B 103건 + SM 77건 = **230건**이다. C01~C16은 감사 쟁점 식별자이며 새 정책 16건을 추가한 것이 아니다.
- 최초 감사의 직접 충돌 2개(C01·C02)는 기확정 A안으로 해결됐다. 이번 대조에서 남은 직접 상충은 0개 묶음이다. 법률·사업·범위의 별도 검토는 계속 남는다.
- C01 표본·C02 문구·C03 최소 진위 권한·C04 계약 단위 분쟁 기준은 보존한다. C05 지표별 정렬/필터, C06 혜택 순서, C07 판단 절차, C08 탈퇴/재가입/잔존 거래, C09 목적별 보존 통제, C10 일정 정지, C11 조건 버전, C12 역할·목적 권한, C13 확인 요청, C14 검증 책임을 후속 결정으로 추적한다.
- 미등록 B14 참조는 원문을 유지하고 C12로 연결한다. 번호를 새로 만들지 않는다. A01~A22의 과거 해결 항목을 현재 미결로 중복 집계하지 않는다.
- 기능 목록은 62개 후보이며 분류는 추천이다. 기존 기반의 문서상 존재는 실제 API/UI·알림·통계·서류·장비·운송 구현 완료와 별개다. 이번에 운영 시스템이나 기존 코드 테스트를 실행한 것이 아니다.

## 권고 설계 순서와 의존성

1. D01·D02: 계정/업체 소속·현재 역할·현장·문서 권한, 거래 당사자와 조건 스냅샷·접근 로그. C03·C12의 현재 목적·최소 권한을 적용한다.
2. D04·D09·D11: 기본 요일·개별 날짜·휴무·수신 중지·신고/제외/제재의 독립 사유, 잔여시간·마감·자원 충돌을 합성한다. C10·C11과 SM-12 적용.
3. D01·D05·D08: 지원·수락·양측 승인·계약 확정·날짜별 근무·전체 완료·지급 신고·수령 확인·정정은 독립 상태로 설계한다. C08 잔존 거래의 별도 지원 경로와 C13 확인 요청을 반영한다.
4. D03: 공식 신고 통지와 일정 알림의 성공 기준을 구분하고 알림 ID·상태 버전·채널 결과·전체 안내·마지막 성공 상태·보류/폐기를 명세한다. C05·C14의 추천/제안 경계는 파라미터와 분리한다.
5. D06·D07: C01~C05에 따른 표본/표시·정렬·지표별 산정 예시와 문서 발급/제출/열람/권한/최소 진위 경계를 작성한다. C09 법적 기간은 빈 검토값으로 유지한다.
6. D10·D12: 기존 기반과 정책·요구사항별 격차, 정정·삭제 전파·보존 예외·운영 검증 목록을 작성한다. 실제 변경은 별도 구현 승인 이후다.

## 첫 이용 흐름의 핵심 후보 — 범위 추천

[기능 목록](node-0.1-feature-inventory.md)의 계정·권한·기록·개인정보·알림 기반 위에, 프로필/업체/현장/공고 → 일정/검색 → 지원·제안 → 동일 조건 상호 승인·계약 확정 → 근무·완료 확인 → 지급 등록·수령 확인 → 거래 이력 반영을 첫 흐름으로 추천한다. [이용 흐름](node-0.1-user-flows.md)의 W01~W11·E01~E10을 입력·상태·승인·예외 초안으로 사용한다.

취소·상대방 제외·신고·잔존 거래 지원·정정·권한 회수는 제공 흐름의 필수 보호 의존성이다. 장비·운송이 실제 선택한 거래에 필수면 관련 확인·일정·책임 기능도 함께 필요하다. 자동추천·서류 제출·전자서명 등의 제공 시점은 추천이며 확정하지 않는다. C15 미채택 아이디어와 C16 범위는 명시적 사용자 승인 대기다.

## 다음 단계 검증과 완료 경계

설계에서는 0/1/4/5건 표본, 최근 0건과 누적 이력, 동일 계약 반복 분쟁, 좋은/나쁜 방향 지표, 소속·권한 상실, 철회 후 최소 진위/상세 차단, 신고·자발 정지 중첩, 일부 채널 성공·역순 결과, 탈퇴 후 미지급 확인을 예시로 대조한다. 이는 미래 검증 시나리오이며 이번에 구현·테스트 완료됐다는 뜻이 아니다.

이번 완료는 새 후속 결정 문서 1개와 감사·기능·흐름·준비 문서 4개의 상태 갱신 및 브랜치 문서 커밋이다. 기존 230건 원문·기존 결정 이력·요구사항·코드·DB·API·UI·배포·main을 변경하지 않는다. 별도 법률·사업 검토와 범위 승인 뒤에 상세 설계의 해당 미정값을 채운다.
