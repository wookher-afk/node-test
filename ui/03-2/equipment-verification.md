### 원인과 수정

- 로더의 `sizesByForm`은 빈 객체였다. A안에서 중복되는 3/4/6루베 이하 구간을 삭제한 뒤 버킷 용량은 `specs[1]`, 산적/평적은 상세 필드에 남겨 상단 메뉴와 분리되어 있었다. 캐시 없는 분리 브라우저에서 재현했고 로컬 서버 파일과 작업 파일이 일치했다.
- 31항목의 상단 고정 후보는 전 형태 제공 7 / 일부 형태 제공 4 / 후보 없음 20이었다. 후보 없음은 제원 입력란 자체의 부재와 구별한다. 확인되지 않은 숫자를 채워 해결하지 않았다.
- 기확정 3종을 제외한 28항목에 `현장 규격` 영역을 형태 선택 바로 아래 배치했다. 장비별 핵심 용량·하중·높이·공법·조건을 모으고 나머지 상세 제원·근거는 아래에 유지한다.
- 로더는 장착 버킷 용량(㎥·루베), 산적/평적/모름, 장착 버킷 설명을 같은 영역에 배치했다. 현장 호칭은 선택 입력이며 빈 호칭도 등록 가능하다.
- 28항목은 별도 현장 호칭 입력을 강제하지 않는다. 형태, 경력, 기타 실제 장비명, 보유 제조사·모델 등 기존 필수 조건은 유지한다. 상세 수치를 새로운 등록 필수값으로 만들지 않았다.
- 로더 HL955A 2.8㎥ / HL960A 3.3㎥, 텔레핸들러 MT420H 2t·4m / MT625H 2.5t·6m / MT930H 3t·9m, 리프트 GTL-1230SS 1.2t는 출처 링크가 있는 모델 참고로 제공한다. 실제값·호칭·모델·실차 확인을 자동 입력하지 않는다. 로더 예시는 타이어식, 핸들러 예시는 고정식에만 표시한다. 하중과 높이의 동시 성립을 보장하지 않는다.
- 견인차 구난/적재, 항타기 압입과 장치, 타워크레인 미설치의 불필요한 항목은 숨기되 원문을 보관한다. 다른 공법·장치가 함께 선택된 경우 필요한 항목은 유지한다.
- 기존 숫자 메뉴와 31개 ID, catalog.js·equipment-schema.js·cargo.js는 승인 직전과 동일하다. 굴착기·덤프·카고의 기존 입력 흐름을 유지한다.

### 데이터 보존

기존 `specs`의 인덱스와 `aSpecs` 키를 바꾸지 않고 입력 요소의 위치만 옮긴다. 저장 시 화면 순서 대신 기존 필드 ID로 값을 읽는다. 미입력/직접 입력/모름/해당 없음/미정은 별도 `equipmentSpecStates`에 저장한다. 기존 빈값을 모름으로 바꾸지 않으며 모름으로 바꾼 뒤에도 이전 숫자 문자열을 보관한다. `0`, 초과 배열, 알 수 없는 필드·옵션, 중첩 초안, 충돌 원문과 두 기존 저장 키는 유지한다. 사용자 브라우저 데이터에 접근하거나 정리하지 않았고 분리 브라우저에서 가상 데이터로 검증했다.

## 정책과 예외

상세 제원은 선택 입력이며 기존 형태/현장 호칭·작업경력·기타 실제명·보유 제조사/모델 조건은 유지한다. 형태→현장 호칭→장비별 상세 조건→옵션 순서이며 명세의 세부 선택 흐름을 각 장비에 표시한다. 선택 항목은 기타 직접 입력을 제공하며 숫자는 자동 생성·환산하지 않는다. 근거 URL, 판본·모델 원문, 확인일, 실차 확인 여부를 별도로 기록한다.

- 천공기·항타기: 공법과 장치 복수 선택, 본체 별도 입력. 불필요한 제원은 해당 없음으로 기록.

- 스크레이퍼: 기존 평적/산적 제원 분리 유지, 보울 방식·연결조건 추가. 해외 모델 급수 없음.

## 저장 호환성

두 기존 저장 키와 기존 마이그레이션·복구 경로를 변경하지 않았다. 신규 상세 제원은 각 기록/초안의 `equipmentDetails`에만 추가한다. 기존 위치 기반 `specs`를 재해석하거나 객체로 변환하지 않는다. 기존 배열의 초과 제원·알 수 없는 옵션·알 수 없는 추가 필드·하위 필드·이전 선택값을 보존한다. 장비별 중첩 초안·충돌 원문·원본 키 백업도 기존 방식으로 유지한다.
